## 二、低显加速流拆解

### 2.1 工作流结构 (极简, 官方流整理)

- 底子是**官方工作流整理优化**, "没有加入其他节点/没有复杂的东西" [04:25-04:36]
- 额外只加两样: **KJ 的"CHH"加速节点** (音译不确定, 推测=KJNodes 的 ChunkFeedForward/LowVRAMAttention 一类, 用户 KJNodes 新版已含) + 一个 4 步 LoRA [04:14-04:25]
- 该 KJ 节点"也防止炸显存" [04:17-04:21]
- 前提铁律: **内核每次开启先更新到开发版最新** (版本管理→开发版→刷新列表), 节点也检查更新到全绿 [03:01-03:55]
- 整合流形态: 文生/图生/首尾帧/多参/四视图同页, 每流底下一个"杠"快捷开关 (开=正常色, 关=紫色), **跑哪个开哪个, 其余全关** [02:10-02:46] — 与用户合集的 Fast Groups Bypasser 同范式

### 2.2 TE/T 加速节点 (本视频核心增量)

- 接法: **LoRA 之后、模型引导(ModelSampling)之前**串入; "这三个功能都是这么加" [07:11-07:22], [12:58-13:08]
- 常态提速 ~20% (仅对**采样**有效, 解码不受影响) [07:28-07:31], [08:24-08:29]
- 原本"加了4步lora就不推荐再加加速节点", 但作者**前一晚零点紧急更新适配了4步lora** (加入"Sp lora"选项), 宣称不损画质再提速20% [07:33-07:47], [09:02-09:16]
- 免安装: 网盘拿插件直接丢 custom_nodes 目录 [09:19-09:25]
- 画质对比 (同一素材开/关节点): "肉眼几乎难以看见区别" [08:44-08:48], [12:45-12:56]; 严谨表述是"有所损失但几乎肉眼难辨, 要求不苛刻完全可以加" [13:30-13:41]

### 2.3 显存/缓存管理策略 (反直觉, 重点)

- **禁止加清理显存/清理缓存节点**: 加上后生成时间大增 (40s级→显著变慢), 与群友"奶爸"联合实测确认, 机理不明 (疑似占内存分配机制) [05:20-05:55]
- ComfyUI 现已智能: 运行新工作流加载新模型时**自动卸载上次残留模型**, 无需清理节点 [23:17-23:31]
- 手动"卸载释放模型和节点缓存"按钮只在**切去跑其他大程序** (如 Photoshop, 音译"Foodshop"推测) 前点一下 [23:34-23:56]
- 缓存红利: 第二次运行采样从 ~60s 掉到 ~30s, "就是这么夸张, 因为显存里不需要重新加载" [06:52-07:08], [27:38-27:47]

### 2.4 实测数据 (0.4MP ≈ 480×864 竖版, 5s, 4步lora)

### 2.5 低显存路线 (GGUF)

- 官方不推荐 GGUF: "会影响内存分配机制" (音译"内盆") [09:56-10:04]
- 体积: 官方原版 ~20G vs GGUF 十几G; 官方 Qwen3VL-32B clip (音译"Charm32B") 25-27G vs GGUF clip 十几G / Q2 仅7-8G [10:04-10:21]; q4 GGUF 18.9G ≈ 原版 int8 19.5G "没差多少", q3 14.5-14.9G 但画质有劣化 [33:04-33:27]
- **GGUF 速度 = 官方 Int8, 零提升** (多次强调) [10:29-10:35], [11:51-11:57]
- 切换接法: 用一个"AndroidShift"切换节点 (音译不确定) 把 GGUF unet / GGUF clip 接入, 想回原版再接回 [10:35-10:52]
- 显存门槛: **12G 不用 GGUF 也跑得很快, 8G 估计也行 (未实测)**; 建议先试原版 Int8, 实在跑不动再 GGUF [11:20-11:41], [29:04-29:22]
- 精度排序 (H3): **Int8 > FP8** ("在Cry2里FP8比Int8好, 但H3里Int8比FP8好, 大量测试测出来的") [10:52-11:10]; 细分: CUDA 13.0 环境 → int8 绝对首选; CUDA 12.8 环境 → fp8 反而可能更好 [33:27-33:48]
- NVFP4 clip 仅 50 系可用, 40 系用 int8 clip [31:06-31:22]

### 2.6 对用户 48G 卡的价值判定

## 五、提示词技巧 (最重要节)

> ⚠️ 总限制: 视频提示词均为**屏幕展示**, 口播为中文讲解, 转写稿中**没有成段英文提示词原文**。可保留的英文碎片仅: `picture1` / `picture2` / `ref_0` / `first` / `last`。完整英文格式模板需从网盘工作流或官方 skill 文档获取 — 此处按转写稿如实蒸馏。

### 5.1 总纲

1. **H3 (音译"A13/mini A13") 有专有提示词 skill/格式**: 不按格式随意写也能跑 ("女人变化姿势镜头推进"这种就行), 但**按格式写支持更好** [14:06-14:36], [14:15-14:26]
2. 官方 skill 走 API 在线; UP主做了**本地版**: Qwen3-4B Q4_K_M GGUF (音译"千万3.54B Q4KM"/"签名3.5"), 模型仅两个多G, ~10秒出词, "不需要再去玩API"; 但承认 "API 可能效果更好, 毕竟是闭源大模型 (音译'必愿搭'推测)" [01:39-01:52], [26:01-26:12], [28:50-29:03]
3. 本地模型放 `models/llms/` [31:00-31:04]

### 5.2 提示词增强节点操作规程 (逐条)

1. **节点接管**: 把增强节点直接拖到提示词输入框上, 松手即被接管; **绝不能加转接点 (reroute), 否则 @ 识别不到图** — "有些人为什么@不出来图, 就是因为接了转接点" [18:30-18:44], [18:58-19:05], [26:39-26:49]
2. **@寻址**: 提示词里打 `@` 弹出已上传的参考图, 选图后生成 `图片1的人物` / `图片2的人物` 式表述; 示例口播原文: "图片1的人物…与这个图片2的人物一起走在街道上" [18:49-19:26]
3. **每次运行前四步检查** [21:02-22:56]:
   - ① **选任务类型**: 全模参考 (多参) / 文生图 / 首帧生图 (=图生视频) / 首尾帧 / 尾帧 — **不同类型内部 skill 不一样** [21:06-21:21], [21:42-21:56]
   - ② **首尾帧接法**: `first`=首帧, `last`=尾帧, 接哪个就是哪个, 落板/起步都可选 [21:23-21:36]
   - ③ **视频时长必须与生成设置一致**: "你设置5秒它按8秒写了很多东西, 结果5秒时间不够用" [22:02-22:17]
   - ④ **先单独运行增强节点**方便调整 → 复制结果到正式提示词框 → **出片前屏蔽增强节点** (种子不固定, 不屏蔽会重跑一遍=电脑跑两个工作流); 不想调整也可直接串入跑, 跑完自动卸载 [22:23-22:56]
4. **自动卸载模型开关必须开** (生成后自动卸载模型), 否则占着内存影响前面 H3 生成 [19:44-19:56]; 缓存里残留模型也是增强节点首次慢的原因 [19:56-20:03]
