## 二、LLM 模块（v10 视角）

### 2.1 执行原则

v10 不追求"本地部署最大模型"，而是追求：

1. **文案可复用**：建立结构化模板库，减少每次调用 LLM 的随机性。
2. **成本低**：优先用云端 API 或已部署的轻量服务。
3. **速度够快**：短视频文案生成不需要 72B/14B 级别的推理，关键是 prompt 工程。

### 2.2 推荐配置

| 场景 | 推荐方案 | 说明 |
|------|----------|------|
| **中文文案生成** | 任意国产云端 API / 本地 7-14B 轻量模型 | 文案短、迭代快，不需要超大模型 |
| **翻译（EN/ES）** | 云端多语言模型 + 母语抽检 | 机器翻译后必须人工/母语者校对 |
| **实时性要求低** | Ollama / vLLM 本地轻量模型 | 可作为离线备选 |
| **不推荐** | 专门为此项目本地部署 Qwen3-14B / 72B | 增加显存与运维负担，与 v10"先验证后投入"冲突 |

### 2.3 关键提示

- 2026 年模型迭代极快，**不要在 M0 锁定单一 LLM**。
- 文案模板比模型重要：建立"钩子 3 秒 + 信息主体 + 行动号召"三段式模板库。

## 三、TTS 模块（v10 视角）

### 3.1 v10 执行栈

| 语言 | 首选 | 备选 | 备注 |
|------|------|------|------|
| **中文** | Fish Speech | F5-TTS | 音色自然、开源、可本地部署 |
| **英文/高质感** | ElevenLabs | — | API 调用，音色库丰富 |
| **西班牙语** | ElevenLabs / Fish Speech 多语言 | F5-TTS | 以实际测试效果为准 |

### 3.2 旧调研模型如何参考

以下模型在 2026 年仍有竞争力，但**不作为本项目默认方案**：

| 模型 | 旧调研结论 | v10 定位 |
|------|-----------|----------|
| CosyVoice 2.0/3.0 | 中文 TTS SOTA，流式快 | 可选测试，但不作为默认 |
| IndexTTS 2 | 时长对齐优 | 可选测试 |
| GPT-SoVITS v4 | 音色克隆事实标准 | 如需克隆特定音色可评估 |
| Edge-TTS | 兜底免费 | **已废弃，不再使用** |

### 3.3 音色资产管理

- 每个账号/人设绑定固定音色，禁止随意切换。
- 音色文件统一存入 `voices/{fish-speech|f5-tts|elevenlabs.json}`。
- 所有音色必须过"完整试听"门禁，再进入生产。

## 四、数字人驱动与视频合成（v10 视角）

### 4.1 v10 执行原则

**ComfyUI 是唯一主链**，负责：

- 文生图 / 图生视频
- 角色/场景一致性控制
- 抠像、合成、调色
- 导出 1080×1920 / 30fps / 9:16 / 30 秒成品

### 4.2 旧工具栈如何处理

| 旧工具 | 旧调研定位 | v10 定位 |
|--------|-----------|----------|
| MuseTalk | 实时唇同步主推 | 不默认使用；如需在 ComfyUI 内做唇同步，优先用 ComfyUI 节点 |
| LivePortrait | 表情驱动 | 不默认使用；存在商用授权风险 |
| LatentSync | 唇同步 SOTA | 不默认使用 |
| SadTalker | baseline | **已废弃** |
| GFPGAN | 人脸增强 | 按需集成到 ComfyUI 节点 |
| FFmpeg | 后处理 | 保留，用于 LUFS/字幕/封装，但不作为创意合成主链 |

### 4.3 为什么不用 MuseTalk/LivePortrait 作为主链

1. **工作流不统一**：每个工具独立运行，难以版本化和复用。
2. **授权风险**：MuseTalk 权重非商用、LivePortrait InsightFace 模型非商用。
3. **v10 要求"工作流即资产"**：ComfyUI workflow 可 JSON 化、Git 版本化、参数可调。

### 4.4 推荐 ComfyUI 节点

| 用途 | 节点包/方向 |
|------|-------------|
| 文生图/视频 | SDXL / Flux / Wan2.1 / HunyuanVideo 等 ComfyUI 封装 |
| 角色一致性 | IPAdapter / InstantID / ControlNet |
| 视频/动画 | AnimateDiff / Video Helper Suite |
| 抠像/遮罩 | Segment Anything |
| 调色/导出 | Color Correction / LUT / Video Combine |

> M0 目标是"文生图 → 图生视频/动画 → 合成 → 导出 30 秒 9:16"能 1 分钟出 3 条。先跑通最小闭环，再扩展节点。

## 五、新闻源（保留并修正）

### 5.1 推荐数据源

| 类型 | 工具/源 | 用途 |
|------|---------|------|
| **通用 RSS 聚合** | RSSHub | 微信公众号、知乎、微博等无 RSS 站点 |
| **财经数据** | AKShare | A 股/期货/基金/宏观 |
| **股票数据** | Tushare Pro | 行情、财务、概念板块 |
| **热榜** | 新浪财经、微博热搜、抖音热榜 | 社交热点 |
| **新闻 API** | 聚合数据 / 天行数据 | 通用新闻（按需付费） |

### 5.2 推荐链路

```
RSSHub / AKShare / feedparser → 去重 → 文案模板库 → 人工/半自动改写 → TTS → ComfyUI workflow → 导出
```

- v10 不追求全自动新闻播报，M0-M2 先验证"给固定文案就能稳定出片"。
- 新闻自动化抓取可作为 M2 后的效率增强项，不是前置条件。

## 六、发布平台（v10 视角）

### 6.1 平台优先级

| 平台 | v10 优先级 | 内容形态 | 备注 |
|------|-----------|----------|------|
| 抖音 | P0 | 9:16 短视频 | 主战场 |
| 视频号 | P0 | 9:16 短视频 | 私域联动 |
| 小红书 | P1 | 9:16 视频 + 1:1 图文 | 封面重要 |
| B站 | P1 | 9:16/16:9 中视频 | 长尾流量 |
| 头条 / 西瓜 | P1 | 9:16/16:9 | 中视频计划 |
| YouTube | P2 | Shorts / 16:9 长视频 | 素材复用池与长尾变现 |

### 6.2 旧调研平台结论如何修正

- 旧调研主推"YouTube + B站 + 公众号"合规三角，v10 改为**国内平台优先**。
- YouTube 不做主推：Shorts RPM 极低（$0.01–$0.07/千次），长视频门槛高，仅作为复用池。
- 公众号可作为内容分发补充，但不是 P0/P1 短视频平台。

### 6.3 发布自动化现状

| 平台 | API/RPA 现状 | v10 策略 |
|------|--------------|----------|
| YouTube | Data API v3 成熟 | M2 后复用国内素材发布 |
| B站 | 创作中心 API | 可用，但非主战场 |
| 抖音 | 仅企业合作 | 个人号先手动发布 |
| 小红书/视频号/快手 | 官方未开放 | 手动发布，不依赖第三方 RPA |
| 公众号 | freepublish API | 文字/图文分发可用，非短视频核心 |

## 七、实时直播链路（明确排除）

**实时数字人直播不在本项目当前范围内。**

原因：

1. v10 当前目标是**短视频**（30 秒、可批量、可复盘）。
2. 实时直播需要独立的推流、合规、互动、风控体系，会稀释 M0-M2 工作流验证精力。
3. 2026-07 YouTube 等平台对 AI 直播/数字人讨论敏感话题监管趋严。

**如需保留技术档案**，可将实时直播调研另存为 `archives/实时数字人直播技术调研-20260720.md`，但不纳入 v10 执行计划。

## 八、AIGC 合规（保留要点）

v10 导演守则已要求平台合规，技术调研层面保留以下要点：

1. **可见标识**：视频或简介中显著标注"AI 生成" / "AI 数字人"。
2. **元数据标识**：在 MP4 metadata 中写入 `comment=AIGC` 等字段。
3. **平台勾选**：发布后台勾选"内容含 AI 生成"。
4. **禁区**：数字人不得讨论金融/法律/医疗；不得擦边/性暗示；不得冒充真人。
5. **国内平台**：先审后发，避免政治、医疗、金融敏感词与夸大标题。

## 九、硬件与部署（v10 视角）

v10 执行以 [M0-GPU-checklist.md](M0-GPU-checklist.md) 为准。本文档仅做原则性提示：

| 等级 | 策略 |
|------|------|
| ≥12 GB 显存 | 完整 ComfyUI workflow 本地运行 |
| 8-12 GB | 完整 workflow，启用 fp16 / 降低视频节点分辨率 |
| 6-8 GB | 简化 workflow |
| <6 GB / 无独显 | 本地设计 workflow，渲染走云端（RunComfy / ComfyICU / ElevenLabs） |

**不要为 LLM 本地部署单独采购硬件。**
