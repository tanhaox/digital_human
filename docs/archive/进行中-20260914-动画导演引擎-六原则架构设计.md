# 进行中 · 动画导演引擎 — 六原则架构设计 (2026-09-14)

> 用户令: 稿→音频已完成, 现在要走视频+剪辑。旧动画产线 (outputs/动画/) 不满意,
> 体外重设计。本文档 = 六原则定稿 + 各模块技术方案 + 确认节点设计。

## 一、六原则 (定稿)

| # | 原则 | 层级 | 一句话 |
|---|---|---|---|
| 1 | **音频先行** | 技术 | TTS manifest 是时间骨架, 镜头时长 = 音频段落实际时长 (含气口) |
| 2 | **运动驱动分镜** | 创意 | 先设计"什么运动在讲故事"(扩张/时间流逝/变形), 按运动节拍切镜, 不按句子配图 |
| 3 | **双向增益** | 创意 | 画面补充/放大/对比口播, 不复述口播 (文字说原因画面给结果, 文字说结论画面给冲击) |
| 4 | **时间预算** | 工程 | 镜数和运动复杂度必须装进音频时长的盒子 — 6 秒的句子不做 3 镜, 规划器做预算内最优设计 |
| 5 | **序列内连贯** | 局部 | 同一叙事弧内色彩/风格/人物/时代感一致, 禁"变形金刚→魔戒"穿越 |
| 6 | **全片统一风格** | 全局 | 一部片子一份美术圣经 (Style Bible), 像迪士尼 — 从头到尾一个视觉身份 |

## 三、模块技术方案

### 模块 A: 美术圣经 (Style Bible) — 书级/系列级资产

- **产出时机**: 建书后、首集导演规划前, 一次生成全系列复用
- **生成方式**: LLM (pro) 吃书名+灵魂三问+受众地图+六拍开场文案 → 产出:
  - 美术风格关键词 (英文, ComfyUI prompt 前缀)
  - 色彩体系 (主色/辅色/情绪色/禁用色)
  - 线条/质感 (扁平/厚涂/水彩/3D → 选一, 全片锁定)
  - 角色设计规范 (如需角色: 定妆照提示词, 已有四视图体系)
  - 文字/图形融合方式 (大字卡底色/字体风格/动画入场方式)
- **落库**: input_json.美术圣经 (与受众地图同级)
- **消费**: 每个镜头的 image_prompt 必须以圣经前缀开头

### 模块 B: 叙事弧切分 + 运动设计 (导演核心)

- **输入**: 确认稿 (script_text) + TTS manifest (每行/每包精确时长 + 气口)
- **处理** (LLM pro, 一次调用):
  1. 读 manifest: 每个音频段落 = 一个时间块 (精确到毫秒)
  2. 将时间块组合成**叙事弧** (一个弧 = 一段完整的叙事意图, 如"HBO 从小到大的反差")
  3. 对每个弧, 设计**运动叙事** ("HBO 标志从灰暗小店快速扩张铺满北美, 40年时间飞速流逝")
  4. 在弧的时间预算内, 按运动节拍切分镜头 (预算约束: 每镜 ≥2s, 镜数 = floor(弧时长/最短镜时长))
  5. 每镜输出: shot_id + t_start/t_end (对齐音频) + 运动描述 + keyframe 画面描述 + 运镜指令
- **输出**: shots.json (同老系统 schema, 但分镜依据从"逐句配图"变为"运动节拍")

### 模块 C: 提示词生成 (keyframe 图 + 动画指令)

- **输入**: shots.json + 美术圣经
- **处理**:
  - 每镜: 圣经前缀 + keyframe 画面描述 (中文→英文) → ComfyUI image prompt
  - 每镜: 运动描述 → 视频生成 prompt (Kling/Hailuo/本地 ComfyUI video)
- **关键约束**:
  - 同一弧内所有镜头共享画面主体/场景 (只变角度/距离/时间, 不换场景)
  - 提示词模板化: [圣经前缀] + [场景描述(弧级共享)] + [本镜视角/运动] + [光线/氛围]

### 模块 D: 确定性校验 (打回闸门)

| 校验项 | 方法 | 打回条件 |
|---|---|---|
| 时间轴连续 | 相邻镜 t_end == 下镜 t_start | 间隙 > 0.1s |
| 时长对齐 | 每镜 t_end - t_start == 音频 manifest 对应段时长 | 偏差 > 0.2s |
| 圣经继承 | 每镜 prompt 以圣经前缀开头 | 缺前缀 |
| 弧内连贯 | 同弧内所有镜头的场景关键词 bigram 重叠 ≥60% | 换场景 |
| 密度合规 | 每镜 ≥2s, 弧内总镜数 ≤ floor(弧时长/2) | 超/欠 |
| 双向增益 | 台词关键词 vs 画面关键词: 禁全量复用 (画面必须含台词没有的新视觉信息) | 画面=台词的直译 |

### 模块 E: 人眼验收节点 (与口播稿"人耳验收"同构)

- **产物**: QC 面板 (复用 qc_sheet.html 模式) — 每镜: keyframe 图 + 动画预览 + 台词 + 时长
- **操作**: 逐镜审 → 不满意的单镜重roll (换提示词重生成) → 满意后确认
- **确认后**: 解锁 ComfyUI 自动产线 (生图→生视频→拼合→合成)

### 模块 F: ComfyUI 产线 (自动执行)

- 确认后无人值守:
  1. 逐镜生图 (ComfyUI API, 圣经+提示词, 支持批量)
  2. QC 图 (可选 VLM 审美打分, 不合格自动重roll ≤3 次)
  3. 逐镜生视频 (图→视频, 按目标时长)
  4. 拼合: 音频 + 视频 + 字幕 → 成片
- **失败处理**: 单镜失败不阻断 (黑屏占位 + 标记, 后续手动补)

## 四、数据流

```
TTS manifest.json
  ├── segments[]: {index, text, duration, file, line_indices, breath_pause}
  └── 总时长 = 所有段 + 所有气口

输入 → 模块B(叙事弧+运动+分镜) → shots.json
         ↓                    ↓
    模块A(圣经) ──────→ 模块C(提示词) → 模块D(校验) → 打回/通过
                                                        ↓
                                                  模块E(QC面板) ← 人眼
                                                        ↓ 确认
                                                  模块F(ComfyUI 自动产线)
                                                        ↓
                                                      成片
```
