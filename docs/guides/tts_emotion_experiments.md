## 三、IndexTTS 机制 (infer_v2.py)

- `emo_vector` 或 `use_emo_text` 存在 → `emo_audio_prompt` 强制置 None (行340)
- qwen 识别整段 → 8维向量 (行345-352)
- `emo_alpha` 在向量路径 = **直接缩放向量值** (行354-362), 不是混合权重
- 向量非空 → `emovec = emovec_mat + (1-Σweight)*emovec` (行497) ← **音色漂移根源**: Σweight 越大, 预训练 emo_matrix 占比越高, 音色越偏
- 双音频分离 (`emo_audio_prompt` 显式传, 无向量/qwen) → 音色与情绪特征分开 merge (行488-494), 但情绪类型受参考音频限制

| 文件 | 段 | 用户反馈 |

| **para3_investor.wav** | **⚠️投资人反转(qwen判愤怒)** | **❌ 接受不了** |

**para3 硬伤根因**: 内容是在**转述投资人对创始人发火**("拍桌怒斥"), 是叙述轶事; qwen 却让主播**整段愤怒**, 语境错配 → 听感灾难. 这类"转述他人情绪"段落稿子中高频出现, 是硬伤.

### 方向结论

- qwen 段落自动识别: 约一半准, 部分不准但被 α0.4 压住可接受, **但 para3 类不可接受** → **不能作为唯一依赖**
- 主方案: **LLM 洗稿时给每段标语义情绪** (现有 [calm]/[serious] 标记扩展为 [calm]/[serious]/[angry]/[excited]/[sarcastic] 等), LLM 懂文意比 qwen 0.6B 准, 可控
- qwen 段落识别可作**兜底/辅助**, 不作主依赖

## 七之四、indexTTS split_segments 词断裂 bug 修复 (2026-08-13)

**现象**: 段落音频中"绝望"被读空 (para3_investor.wav), whisper 转写"排到絕\n望更".

**根因**: `indextts/utils/front.py::split_segments_by_token` 超限时按固定长度硬切, 把中文词从中间切断. para3 累积到 121 tok 恰好停在"绝", 逗号递归切出段2"开发者排队接入排到绝"(21tok), "望"被甩到下一段 → 词断裂 → 段尾字丢失.

**影响**: 所有 >120 token 长稿都可能出现词切断/字丢失 (所有真实稿子).

**修复**: 新增 `split_segments_fixed` (front.py), 超限时回退到最近标点切, 词中间字段(carry)留到下一段继续累积; 保留原合并逻辑. `split_segments` 改调 fixed. 备份: `front.py.bak_20260813`.

**验证**: 分词模拟 para3 词断裂=0, 整篇误报4个(实为"绝大多数/绝非/绝对"等完整词); 真音频 whisper 确认"排到绝望"完整读出.
