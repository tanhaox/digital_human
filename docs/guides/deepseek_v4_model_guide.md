# DeepSeek V4 双模型使用指南

> 本指南用于 `digital_human` 项目内部参考，帮助开发者在调用 DeepSeek V4 系列模型时，正确组合使用 **Pro** 与 **Flash**，兼顾质量与成本。

## 核心原则

**Pro 是“大脑”，Flash 是“手脚”。** 两者不是简单的强与弱，而是分工明确。实践证明，**将两者组合使用效果远超单独使用任何一个**。

| 对比维度 | DeepSeek-V4-Pro（专家/规划者） | DeepSeek-V4-Flash（执行者/快手） |
| :--- | :--- | :--- |
| 定位 | 高性能专家模型，深度推理，处理复杂任务 | 高性价比快速模型，低延迟，高吞吐，高频调用 |
| 参数规模 | 总参数 1.6 万亿（1.6T），激活参数 490 亿（49B） | 总参数 2840 亿（284B），激活参数 130 亿（13B） |
| 推理成本 | 较高（约 Flash 的 3 倍） | 极低，官方定价约输入 $0.14/百万 tokens，输出 $0.28/百万 tokens |
| 响应速度 | 较慢（深度思考耗时） | 快（秒级输出） |
| 核心优势 | 深度推理、架构决策、复杂调试、多文件联动 | 快速执行、高性价比、批量操作、低延迟 |
| 适用场景 | 项目规划、系统设计、根因分析、代码审查、复杂算法 | 代码生成、代码重构、文档总结、日常问答、Agent 工作流 |
| 最大弱点 | 对简单任务过度思考，输出冗长，成本高 | 处理模糊指令效果不佳，复杂任务上能力弱于 Pro |

## 核心工作流：Pro 规划 + Flash 执行 + Pro 审查

这是最大化利用两者优势、平衡质量与成本的最佳实践。

### 阶段一：规划（使用 Pro）

- **做什么**：分析需求，拆解任务，输出详细的执行方案。
- **为何用 Pro**：规划需要深度理解上下文、识别边界、评估风险，这是 Pro 的强项。

### 阶段二：执行（使用 Flash）

- **做什么**：严格按照 Pro 的规划编写代码、修改文件、进行批量重构。
- **为何用 Flash**：执行环节消耗 60%-80% 的 tokens，用 Flash 成本仅为 Pro 的约 1/12，且在明确指令下质量与 Pro 差距极小。

### 阶段三：审查（使用 Pro）

- **做什么**：审查 Flash 生成的代码，检查边界条件、安全性、跨文件一致性等。
- **为何用 Pro**：审查的 token 消耗远小于执行，用 Pro 做质量兜底，成本增加有限但质量提升显著。

## 在本项目中的具体应用

### 编程与软件开发

直接应用上述三阶段工作流。

- **规划阶段**：用 Pro 进行系统设计和接口设计。
- **执行阶段**：给 Flash **明确、具体**的指令完成代码生成和文件修改。
- **审查阶段**：用 Pro 检查代码逻辑、安全与风格。
- **Temperature**：编码/逻辑任务建议 `0.1 - 0.3`，以获得更确定性的输出。

### 长文档处理与分析

两者均支持 **100 万 tokens** 上下文窗口。

- **总结、信息提取**：优先使用 **Flash**，成本极低且速度飞快。
- **深度推理、交叉验证**：使用 **Pro**。
- **防幻觉技巧**：在 Prompt 中添加强约束——“仅基于我提供的文本进行回答，禁止使用外部知识”。
- **超长文本**：采用“分块切片法”逐步分析。

### 日常文案与内容创作

- **周报、邮件、新闻稿、营销文案**：用 **Flash** 完全足够，响应迅速且成本极低。
- **战略报告、深度分析文章**：规划阶段用 **Pro** 生成大纲和核心论点，再用 **Flash** 扩写。
- **Temperature**：创意/发散任务建议 `0.7 - 0.9`，以获得更具创造性的文本。

### 知识库问答（RAG）与客服机器人

- **大多数用户查询**：**Flash** 是理想选择，快速、低成本。
- **复杂、多步骤查询**：路由到 **Pro** 处理。
- **Agent 工作流**：使用 **Flash** 进行高频率、低成本的工具调用和子任务处理。

## 项目配置映射

本项目在 `config/app.yaml` 中配置了两个模型别名：

```yaml
deepseek:
  api_key: "${DEEPSEEK_API_KEY}"
  base_url: "https://api.deepseek.com"
  model_flash: "deepseek-v4-flash"
  model_pro: "deepseek-v4-pro"
  default_model: "flash"
```

在调用洗稿接口时，可通过 `model` 字段切换：

```json
POST /api/articles/{id}/rewrite
{
  "model": "flash"
}
```

允许的值为：

- `"flash"` → 映射为 `model_flash`（快速执行，默认）。
- `"pro"` → 映射为 `model_pro`（深度思考）。
- 也可以直接传入具体模型名，例如 `"deepseek-v4-pro"`。

## 最佳实践速查

- **日常开发用 Flash，复杂问题切 Pro。**
- **混合使用**：Pro 规划 + Flash 执行 + Pro 审查。
- **巧用思考模式**：调用时可通过 `reasoning_effort` 参数设置思考强度（`high` / `max`）。**Pro + 思考模式**是处理最难问题的终极组合。
- **明确 Prompt**：给 Flash 的指令必须清晰、具体，避免模糊。
- **控制 Temperature**：编码/逻辑任务用低温度（0.1 - 0.3）；创意/发散任务用高温度（0.7 - 0.9）。
- **技术集成**：两者共享相同 OpenAI 兼容 API 接口，可在支持 OpenAI 协议的工具中轻松切换模型。

## 总结

DeepSeek V4 的 Pro 和 Flash 并非替代关系，而是互补的黄金组合。通过理解它们各自的优势，并根据任务类型灵活调度，可以在保证项目质量的同时，实现显著的降本增效。
