## 一、病理

`目标读者画像` 的旧链路 (0907 立): L0 建书主路径 `auto_fill_from_l0` 直接继承
`persona.target_reader` (账号人口学, tier=persona); facing 三面 (units/hooks/readers
= 选题角度/钩子/读者痛点) 的受众指纹校验也拿 persona 当基准 — **整条受众链从账号来,
书的内容从未参与**。

HBO 实锤: 目标读者画像 = "25-50岁男性为主、有升职愿望的职场人…" (persona 原文),
而书自己的读者信号就躺在蒸馏料里没人用 —
`facing-kernel.why_read` = "内容创作者和平台运营者急需摆脱流量陷阱"。
下游代价: 读者共鸣料按账号人口学生产 → 钩子认领"带团队的/做账号的/想往上走的"
大礼包 (ep2 钩子病根之一)。

## 二、修复 (受众来源四点翻转)

新增 **【书目读者锁定器】** `_derive_book_reader` (creation_steps.py):
料=kernel 内核 + L0 章节概念 + 书页 blurb (受众无关面, 不吃 facing 三面重跑);
flash 调用, 输出 {reader, evidence, eligible}。提示词三铁律:
- 禁账号定位/人口学套话 (那是"讲给谁听", 不是"书为谁写");
- **同构处境**: 书讲行业案例时读者≠该行业从业者 (拆HBO≠只给电视人看) —
  读者=现实中处境被同一机制摆布的人; 沾边 (好奇/想提升) 不纳入;
- 画像=处境+决策场景, 能直接当开篇筛选器; 锁不住 eligible=false → persona 兜底。

| 调用点 | 旧行为 | 新行为 |
|---|---|---|
| auto_fill_from_l0 字段填充 | persona 继承 | 书定读者 (tier=L0+evidence); persona 只兜底 |
| auto_fill_from_l0 指纹校验 | persona 当受众基准 | 书定读者当基准 (0907 的"全能妈妈"病同治) |
| build_comment_layer | **persona 优先且漏传 book** (拿默认 host 的人设) | 书定读者 > 本书 persona > 旧值 |
| rerun_outline→recut_units | 受众继承旧指纹链 | 书定读者优先, 未锁定才继承链 |

- `_book_reader_value`: tier≠persona 才算书级有效值 — persona 继承值视为"未定",
  下次补全自动重新锁定 (人工填的保留)。
- UI: 内容库页徽章 persona → 「来自人设·兜底」, 书定 → 「来自书内容」。
- 顺手修: complete_input (手动路径) 提示词补锁定要求, 防 LLM 又给人口学套话。

## 三、真实数据验证 (HBO)

锁定器现场跑两轮校准: 第一轮锁成"流媒体平台负责人" (照字面锁进书的行业 —
提示词缺陷), 补"同构处境"铁律后第二轮:

> reader: 收入依赖流量广告或平台分成、数据好看却不挣钱的内容团队/平台负责人，
> 正决定继续做分发渠道还是投入自制精品，以质量换订阅留存。
> evidence: HBO从付费电视分发商转向原创内容生产，用"少而精"建立品牌护城河。

全程零账号人口学。HBO 库字段已更新 (tier=L0), 内容库页即见「来自书内容」徽章。
