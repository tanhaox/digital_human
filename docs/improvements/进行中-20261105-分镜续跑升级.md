## 批 2 — 同集互斥闸 + 锁纪律 ✅ (2026-11-05)

**改了什么** (治 病灶2+11):
- start_phase: 同集闸与 job 注册同一临界区 (防双开竞态) — 同 (book, ep) 已有 running job → 409; GPU 相位被拦时预取的 GPU 锁放回 (防全局死锁)。
- `_ep_lock_timed` (10s 超时): plan/replan job 线程不再无限阻塞等 `_ep_lock` (旧版 GPU 批期间挂死几十分钟零进度)。
- redo 移出 GPU_PHASES 预取群: LLM 重设计段 (N×3.5min 零 GPU) 不再占 `_GPU_JOB_LOCK` 挡其他书 GPU 批; 转 GPU 一条龙前 `_wait_gpu_lock` 现场取锁 (15s 分片等待+进度日志, ⛔可中断; 被停 → gpu_skipped 结果指路手动 K2, 不算失败)。

**为什么**: 旧版同 ep 双 plan job 并存注册、第二个阻塞后照跑/假失败; redo 的 LLM 段占 GPU 锁致他书 GPU 空转被挡。

**验证**: tests/test_anim_mutex.py 5 用例 (409 闸/锁回放/超时锁/等待中断/接线断言) 全绿; 全量 **6f/515p** (+5)。GPU 锁取放平衡现场 grep 复核 (230→266/310; 401/411→464)。

**兼容性**: replan_all.py 已有 409 重试通路; ep2_remake_monitor4/5 只 GET 不受影响; `.tmp/chain_replan_1028.sh` 盲 POST 对 409 静默吞 (历史一次性脚本, 记录在案)。

**风险**: 同集排队语义变显式 409 (旧=静默排队) — 属预期执法; redo 等待 GPU 期间持 ep 锁 (同集闸下无冲突)。
