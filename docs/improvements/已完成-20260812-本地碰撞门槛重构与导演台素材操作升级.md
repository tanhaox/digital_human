## 升级一：本地碰撞命中率修复（门槛重构，0%→68%）

### 根因链（实测数据）

| 层 | 根因 | 实测 |
|---|---|---|
| **软维度门槛过严** | 6 维一起算 ≥75%，`motion=static≠slow` 就把"暗+机房+氛围全对"的素材刷成 25% | 42 条候选全灭 |
| **空值必失分** | 素材没标 tone = 该维必 MISS（tech 素材 41/42 tone 空） | 3 维门槛恒 67%<75% |
| **多备选值只取第 1 个** | `shot_types=["建筑","特写"]` 只匹配第一个 | 39 条"空镜"素材全配不上 |
| **location 硬过滤一刀切** | 导演 90% 标 domestic，但库 foreign 1215/1672 | domestic 候选仅 5 条 |

### 修复内容

| 文件 | 改动 |
|---|---|
| `asset_matcher.py` | ①**门槛维降 3 维**（scenes/shot_types/tone，3 中 ≥2）；motion/content/time 降为**加分维**（命中加分不排除）。②**空值跳过**：素材未标该维 = 无信息，不记失分；全门槛维空 → 仍排除（宁缺毋滥）。③**备选值交集**：导演给多个值（如 shot_types=[建筑,特写]）任一命中即算该维命中。④**location C 折中**（`relax_location=True`）：先 strict 全中，候选为空才放宽 foreign 并标记 `location_relaxed=True` |
| `broll_pexels.py` | 碰撞 guard 从"任一软维度"改"门槛维 3 个"；`_try_local_collision` 传 `relax_location=True`；放宽时日志标 `LOCATION_RELAXED` |
| `broll.py` | `_match_local` 传 `relax_location=True`；`_strategy_semantic_match` 放宽日志标记 |
| `_prompt.py` + `_constants.py` + `visual_director_v2.txt` | 措辞同步：门槛 3 维、加分 3 维、location C 折中 |

## 升级二：同 job 素材硬排除（一素材一视频只用一次）

### 根因

本地碰撞命中只 `register_asset_usage` 递增全局 `used_count`（**降权不排除**），从不写回 `params_json` → 后续 slot 无法感知前面用了哪个文件。而 `match_local_assets` 最终**按 score 纯排序**，`used_count.asc()` 只影响候选池顺序，无法阻止高分素材被反复选中。

对比：Pexels 在线侧**已有** `_collect_used_pexels_ids` + `exclude_pexels_ids` 硬排除（broll_pexels.py:37），工作正常；本地侧缺失等价机制。

### 修复内容

| 文件 | 改动 |
|---|---|
| `asset_matcher.py` | `match_local_assets` 加 `exclude: list[str]` 参数；`_search` 里 `~VideoAsset.file_path.in_(exclude)` 硬排除 |
| `broll_pexels.py` | 新增 `_collect_used_local_files`（按 `status=completed` 收集，**不按 slot_index 收紧**以覆盖 mixed_host_broll 跨 phase）；命中写回 `params_json["local_file"]`（新建 dict 整体赋值触发落库） |
| `broll.py` | `_match_local` 传 exclude；`_strategy_semantic_match` + `_try_exact_file` 命中写回 local_file |

### 验证

```
真实 job fdca3d40 (83 broll slot) 模拟:
  修复前: V20260807-0012 命中 28 次
  修复后: 13 个本地命中全部不同素材, 无重复; 该素材 1 次
  其余 70 slot 排除后无匹配 → 正确转 Pexels 下载

## 升级三：director 台素材操作三件套

### 3a. 禁用素材标

**问题**：打禁用标（`preference=dislike`）只在素材库页 library.html 有；且**本地碰撞线完全不过滤 dislike**——只有 Pexels 在线 resolve 排除。打了标本地线照样选。

| 文件 | 改动 |
|---|---|
| `retry.py` | 新增 `POST /jobs/{job_id}/slots/{slot_id}/disable-material`：从 slot 反查素材（`pexels_id`→`VideoAsset.pexels_id`、`local_file`→`file_path`、`replaced_asset_no`）→ 设 `preference=dislike` |
| `asset_matcher.py` | `_search` 加 `VideoAsset.preference != "dislike"` 过滤（本地线禁用生效） |
| `broll.py` | `_try_exact_file` 命中前查 dislike 跳过 |
| `director.html` + `director.js` | slot 详情加"🚫 禁用素材"按钮 |

### 3b. 替换去重校验

**问题**：手动贴 asset_no 替换时，若该素材已在本视频其他 slot 用过，无提示。

`retry.py` `replace_slot_material` 加校验：遍历同 job 其他 slot，四者任一命中（`pexels_id` / `local_file` / `file` / `replaced_asset_no`）→ `409 "该素材已用于 Slot #X，一视频一素材"`。

### 3c. 重新生成强制 P 线下载

**问题**：本地碰撞和替换都走死时，点"重新生成"无法强制下载新素材。

| 文件 | 改动 |
|---|---|
| `retry.py` | `retry_slot` 加 `force_pexels: bool = False` query param → 写 `params["force_pexels"]=True`；`broll_local` 槽位切 `broll_pexels` |
| `broll_pexels.py` | `_resolve_pexels` 读 `force_pexels` → **跳过 `_try_local_collision`** 直接走 Pexels 下载（dislike 排除/同 job 去重/配额仍生效） |
| `director.html` + `director.js` | retry 加"强制 P 线下载"勾选框，选中时 URL 带 `&force_pexels=true` |

### 验证

```

## 升级八：爆品改造 P4 全篇精修 + 正文锚点标记

### 背景

用户拿系统版爆品改造稿给豆包评测，豆包评价：整体方向正确（钩子前置/金句/结构/结尾都认可），**唯一硬伤是"前两段重复"**（P1 钩子讲禁令/七百万，正文开头段又复述）；开篇缺"时代危机铺垫"；正文衔接生硬。

用户决策：**P1-P3 保持不动**（豆包拿到的就是它们产物），所有升级放新增 **P4**（扮演"豆包精修"角色）。

### 正文锚点标记（治"前两段重复"根因）

**根因**：`_find_end` 无锚点 fallback 只删 1 行，保留与 P1 语义重复的开头段（"ChatGPT的禁令…七百万"）→ 最终稿前两段重复。

**方案**（用户拍板）：不在 `_find_end` 猜正文起点（正则特征词过拟合），而是**在洗稿模板埋专用锚点标记**：
- `laotan.txt` / `laotan-tech.txt` / `laotan-geo.txt`：模块三前新增【正文锚点·必须输出】——强制 LLM 在"身份段之后、正文正式开始处"单独一行输出 `【888999000】`
- `_find_end`：优先匹配 `【888999000】`（精准），回退引导词锚点，再兜底删 1-2 行
- `clean_boosted_text`：剥离 `【888999000】`（不进 TTS）

**验证**：真实洗稿测试，LLM 稳定在钩子+身份段之后、正文前输出锚点，位置唯一正确。

### P4 全篇精修（编译豆包写作方法论）

`boost_service.py` 新增 `P4_PROMPT`，在 run_boost 的 P1-P3 之后执行，失败回退 P1-P3 产物。

**P4 核心约束**（多轮迭代到最终版）：
1. **信息守恒铁律**：输出字数 ≈ 输入（实测 2792→2963，比 1.06），每个数据/人名/金句保留，逐段对应，只优化表达不改写内容。
2. **开篇 4 层次叙事重组**：时代危机 → 反常现象 → 结果反差 → 悬念升华（段落式，非短句堆叠）。
3. **正文逐段精修**：删重复段、衔接顺滑化、口语化，但不删有效信息/不改论证/不改数字。
4. **保留老谭特色红线**：咱们站位、冷峻毒舌、比喻对应律、短句节奏、金句意识。
5. **播报适配**：有画面感、对听众接受度高（音频转语音后形象固定，文字可脑补）。
6. **情绪标记白名单**：只用 [calm]/[serious]/[confident]，禁自创（修复了 P4 自创 [surprising] 导致 TTS 不识别的 bug）。
7. **身份段/固定结尾**：1:1 保留，位置不强制（0分起号阶段身份不重要，几万粉变现才重要）。

**验证**：P4 v6 输出 2963 字，关键信息全保留（七百万/二十亿/唐杰/中科加禾/金句/结尾），画面感命中超豆包版；孤立 `||` 行被 `_tts_text` 安全处理，不影响音频生产。

### P1 真实性修复（2026-08-12 晚间）

**问题**：P1 电击版为了凑"认知反转"模板，编造原文不存在的情节——存储新闻稿里凭空出现"被骂自杀，结果利润暴涨40倍"（原文 0 处"被骂/自杀"）。

**根因**：P1_PROMPT 第四句"操作"引导"被骂傻→结果封神"，电击示范"投资人骂他脑子有病"——模型把模板当必做，硬编戏剧冲突。

**修复**（boost_service.py P1_PROMPT）：
- 第四句反转改为"必须从原文真实信息提取"（如：消费低迷 vs 业绩暴涨的冰火两重天、缺货却只供企业级），新增【真实性红线】：禁止编造被骂/被嘲讽/被质疑等原文不存在的情节。
- 第三句同理：反常识爆点必须是原文真实信息，禁止编造"蠢操作却成功"等。

**验证**：重跑 P1，新输出四句——"消费级存储正在被AI需求榨干 / 所有人都认为存储该降价 / 巨头锁产能利润暴涨45倍 / 消费惨淡业绩暴涨冰火两重天谁在操盘"——无"被骂/自杀"，45倍来自原文"净利润同比增长4506.02%"，反转基于真实矛盾。

### 数字锚定（2026-08-12 晚间）

**背景**：用户指出"原文信息穿透"问题——我们写稿时有原文，但观众是滑动消费（刚看完上一个视频，没读过原文）。孤立数字（"利润暴涨45倍""营收89.6亿"）对零背景观众云里雾里。用户拍板：**做数字锚定，不做专有名词解释**（专有名词靠人工两次介入：生成前加观点 / 生成后编辑稿）。

**修复**：
- `laotan-tech.txt`：Fish Speech 适配段加**数字锚定硬约束**——每个数字/倍数/金额首次出现必须交代"对比什么/基于什么"（错误示例"利润暴涨45倍" vs 正确"净利润同比去年暴涨45倍"）。
- `boost_service.py` P4_PROMPT：信息守恒铁律加**数字锚定**——精修时逐个检查数字是否带对比基准，未锚定补上（不改变数字本身）。

**验证**：真实跑存储新闻完整流程（洗稿→P1-P4），关键数字全部锚定——"四十五倍"回收为"闪迪同比数字"、"九百三十九亿"带"什么概念→五年协议"解释、配货"六七十吨"对比"要一百吨"。信息穿透用观众可脑补类比（沙子炼特种钢、手机照片容量），HBM 不甩术语（"一只手数得过来"），落地普通人（手机存储定价/云盘成本/创业门槛）。
