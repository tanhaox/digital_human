# 已完成-20260809-P线本地碰撞-ID034匹配修复

**日期**: 2026-08-09
**范围**: `app/services/asset_matcher.py` + `app/services/slot_workflows/broll_pexels.py` + `app/services/slot_workflows/broll.py` + `app/services/director_prompt/_prompt.py` + `config/visual_director_v2.txt`
**状态**: ✅ 已完成

## 背景

P 线（broll_pexels）slot 执行时几乎全部走下载路径，本地 1400+ 视频素材库极少命中（近 2 天 195 个 broll_pexels，0 个 broll_local）。用户要求调查：LLM 生成的导演关键词是否真的与本地 VideoAsset 数据库发生碰撞？

**拍板架构**：LLM 只规划"画面关键词"，不参与"本地还是在线"决策；独立碰撞机制在下载之前执行——命中本地则用本地，未命中才下载。碰撞率低没关系（本地 1400+ 素材覆盖不了全部画面，画面精准比复用价值更高）。

## 根因链（双层）

### 根因 A：提示词把 P 线 9 维度写成"建议"，LLM 不遵守

旧提示词中 broll_pexels 的 9 维度（scenes/shot_types/tone/motion_level/content_density/time_of_day）是"建议输出"，LLM 实际产出率极低——最新 job 50 个 P 线 slot 仅 2 个带完整维度。无 9 维度 → `_try_local_collision` 守卫直接跳过 → P 线全部走下载。

### 根因 B（真正代码 bug）：scenes/shot_types 中文值在 SQLite JSON 转义下 SQL 层被滤光

`match_local_assets` 用 `scenes.cast(String).ilike('%城市%')` 过滤场景/镜头列。SQLite 把 JSON 数组列的中文存成 `\uXXXX` 字面量（`["城市"]` → `["城市"]`）→ 明文 LIKE 永远匹配 0。英文值（tone 等）不转义所以能 work。**这意味着 P/L 两线本地匹配从未真正生效过（非仅最近 2 天）。**

> 另有一个验证陷阱：早期冒烟测试用中文 tone 值（明亮/中/白天），与词表包英文枚举（bright/medium/day）永不相等 → 0 命中。确认 DB 存英文后改用词表包真实枚举值。

## 匹配契约（ID-034）

- **硬维度** location / orientation / people：独立列硬过滤，必须全中，否则排除。
- **软维度** scenes / shot_types / tone / motion_level / content_density / time_of_day：命中率 ≥75%（`MIN_HIT_RATIO=0.75`，6 中 ≥4；传 4 个需全中）。
- **keywords**：词表包画面词，提供额外精确打分（命中 +1），不绑定命中率。
- **精确时长防护**：`render_scale_pad` 无 loop 标志，素材短于 slot 时长会黑尾截断 → 要求 `duration_sec >= slot 精确时长`。

## 素材不复用登记

`register_asset_usage` 只递增 `used_count`/`updated_at`，**不做同 job 硬去重**——本地库规模（1500+）远不足以支撑 107 slot 全去重，由 `used_count.asc()` 排序把高频素材自然降优先级。
