## 病理背景（按挖掘顺序）

1. **撞名覆盖**：ComfyUI `/upload/image` 默认不覆盖同名 input 文件（落 `xxx (1).png`），face_fix/text_pass/erase_pass 三个自造上传器丢弃响应且 LoadImage 引原名 → 加载陈年旧图回写覆盖当日新图（22 镜旧林肯图覆盖天平图、s07/s15/s16 方图事故链）。
2. **场景标签泄漏**：器层 fallback 把中文场景名写进 opening_desc（"scene: 王冠宝石 机械臂"）→ 视频模型当片头大字渲染（58/62 镜中招，s16-21 连四镜【王冠宝石】）。
3. **无脸 72h 根因**：director_prompt.txt 美术圣经段是 HBO 书样板硬编码进共享提示词——"用极简几何剪影(无脸/背影/侧影)不画五官"与本书圣经 character_policy"禁无脸/背影/剪影"逐字对抗；且 character_policy 只喂规划 LLM 从不进渲染链、器层通用人物 look=era_anchor 服饰段零脸向、FACE_LAW 只锚完整性不锚朝向。
4. **规划层假重做**：replan_shot 槽路线对槽词表稳定的镜 flash 填槽+assemble 后画面句逐字不变；成功后不回 planned → K2 待跑 0 镜（"重规划拉不起 K2"）。
5. **双 AI 挤卡**：ComfyUI + llama 同时驻留 48GB 大卡 → 驱动级迟滞（nvidia-smi 卡死、批速跌至 1/3、修脸 4 分钟超时）。

## 教训

1. 检查产线问题时先查**哪个层产的提示词、它读了什么规则**——本集 51/62 镜由 fallback 器层产提示词，其填槽模型读不到任何军规（规则住在了 writer 契约里）。补丁永远落后于设计层欠债。
2. 共享注入字段禁携带任何书特定样板（ID-095 家族第三次实锤：HBO 剪影/吉普力全局句/1940s 卧室）。
3. 多写者靠护栏维持的单一源是假单一源——写者数量本身就是债（beats 模板 7 处、主色尾 3 处、浮字双通道）。
4. 资源互斥要机制化不要纪律化：双 AI 挤卡的每个症状（超时/慢/卡死）都曾被当成独立 bug 修。
5. A/B 是语言之争的终审：一例实锤（1015 s14）升级为同镜对照（1017 s33/s46）后决策不再靠记忆。
