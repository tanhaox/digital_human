## 七、教训

- **脚本批量替换是事故高发区**（本日 3 起：B15×2 误吞 raise/rollback、B16a-W5 丢缩进，全部当场修复）——逐处手工改 + import 验证更稳。
- 审计报告行号/文件数/引用数会漂移，执行前现场 grep 为准。
- 明细清单可能严重不全（B08 清单 2 处实测 20 处；B07 清单 5 处实测 6 处）。
- git stash 是高风险操作，非必要不用（B16c 事故实录）。
- 行号漂移下 grep 窗口/剥离常数容易误判——校验脚本要用锚点定位，不用行数猜。
