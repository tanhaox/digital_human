# 螺旋周检 SOP (2026-09-10 立)

> 节奏 (用户令): **每周一次**, 排在每周账号数据分析之后跑 — 数据分析看结果, 螺旋检决定"要不要动系统"。
> 优先级: **文本层最先** (评分/改稿/coverage 零件最全, 数据已在产); 画面/音色账本配齐后逐层加入。
> 铁律: 螺旋只提案, 人工审批才落; 无账本的改动 = 违规。

## 周检流程 (每周账号数据复盘后, 一条命令)

```
python scripts/spiral_check.py
```

脚本自动盘点并输出开闸判定:

### 闸① 文本元评审 (环②) — 累积 ≥5 集评分+改稿数据
```
输入: .tmp/spiral/ 下每集的 (审片报告 + 改稿 coverage + 首稿/终稿)
动作: 元评审 LLM — 找反复低分维度 + 改稿官反复手修的同类问题
输出: 模板补丁提案 1~3 条, 每条必须引用 ≥2 个具体扣分案例
落点: 人工审批 → laotan-book.txt 修改 → **同步记挎斗账** → 黄金集回归
```

### 闸② 真实数据校准 (环③) — 累积 ≥5 条复盘账本
```
输入: docs/references/复盘-*.md (含掉落点三对齐 + 本期变更项)
动作: 校准分析 — 哪些评分维度与真实完播相关/无关/负相关; 高分低完播=盲点坐标
输出: 评分框架修订提案 (维度权重/补维度/retire_when 触发)
落点: 人工审批 → review_book_score_v1.txt 修订 → 金丝雀重建基线
```

### 数据不够 → 只报库存不开闸
```
本周集数/复盘条数 → 距开闸还差几条 → 下周再看
```

## 开闸后的动作顺序 (一次只动一层)

1. 文本层提案先行 (本周期若多闸同开, 文本最优先)
2. 补丁落模板 = 同步挎斗记账 (WHY/来源案例=本周提案的案例引用/retire_when)
3. 黄金集回归 + 金丝雀基线重建
4. **单变量原则**: 本周若同时改了文案模板和画面, 复盘账本"本期变更项"要如实多勾 — 下次归因降级, 教训记账

## 收敛观察 (螺旋的终点仪表)

- 改稿 delta 连续 3 集 ≈ 0 → 文案模板已吸收可学教训 → 环② 降频 (改稿量是元评审最好的先行指标)
- 评分与真实完播相关性稳定 → 环③ 降频
- 全收敛 → 提分换工具箱: 选题挎斗/画面挎斗/账号阶段 (这正是账本家族的后排)
