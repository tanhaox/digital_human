# 对标视频分析流程 (SOP v1, 0911 立)

> 依据【三条真锚】政策: 别人的存活样本 + 别人的爆款样本是两条外部锚。
> 本流程 = 丢一个抖音链接 → 自动判定它属于哪个锚 → 结构拆解 → 入对标库分架。
> 引擎复用: kimi-webbridge (登录态抓数) + ref-teardown (拆解含画面) + tools/vision。

## 一、数据采集 (webbridge, 丢链接后自动)

**视频页** (https://www.douyin.com/video/{id}):
- 发布日期 / 视频时长
- 点赞 / 评论 / 收藏 / 分享 (访客侧无播放量 — 用互动量代理)
- 作者主页链接

**作者主页** (抓取后计算):
- 粉丝数 / 获赞总量
- 最近 10 条视频的点赞数列表 → 中位数 / 最大值 / 该条视频的相对位次
- 更新频率 (可判活跃度)
- 注册时间: 平台不直接暴露 → 以最早可见视频日期近似, 或人工补 (关键过滤器, 拿不到就标"待补"降级判定)

## 二、阶段判定 (scripts/bench_classify.py, 确定性规则)

| 判定 | 条件 (全满足) | 含义 |
|---|---|---|
| **爆款样本** | 该视频点赞 ≥ 10万 | 结构经大流量验证 — 埋的东西都奏效了 |
| **阶段样本 (冷启动存活)** | ① 账号注册 ≤ 6周 (近似) ② 粉丝 < 2万 ③ 最近10条点赞中位数 50~5000 (活号非死号) ④ 该条点赞 ≥ 账号中位数 × 1.5 (它在乱流里活下来了) | 冷启动同龄存活 — 人群不准也看得下去 |
| **排除: 老号偶发** | 注册 > 3月 且 账号量级大, 仅单条几百赞 | 不是阶段样本 (拿不到冷启动信号) |
| **排除: 死号** | 最近10条中位数 < 20 | 没活下来, 无可学 |
| **中间态** | 其余 (几千~几万赞) | 记录观察, 不入两架 |

边界弹性: 规则阈值集中在 config/bench_thresholds.json — 政策允许随赛道校准, 改阈值不改代码。

## 三、拆解深度按架分流

| 架 | 拆什么 | 工具 | 校准对象 |
|---|---|---|---|
| 爆款架 | **全篇结构** teardown: 钩子型 / 论证顺序 / 伏笔回收链 / 节奏曲线 / 金句形态 / **画面-文案配合度** (画面何时托文案/何时替代文案) | ref-teardown + tools/vision + 逐段字幕 | 六段结构 + 构件调度表 (结构升级提案候选) |
| 阶段架 | **轻拆解**: 前 3 秒钩子形态 / 完播结构猜测 (时长+节奏) / 选题-人群匹配方式 | 视频页观察 + 字幕转写 | 维度 1/7 的冷启动刻度 |

## 四、入库与消费

```
对标库: .tmp/benchmarks/
  hits/    爆款架 (YYYYMMDD_<账号>_<vid>.md — 判定依据 + 结构拆解)
  stage/   阶段架 (同构)
  mid/     中间态观察
消费: 螺旋周检时 — 阶段架校准维度1/7刻度; 爆款架出结构升级提案
      → 人工审批 → 挎斗记账 → 黄金集回归 (同一审批闸, 不开新门)
```

## 五、判定输出的必答字段 (可审计)

每条判定输出: {判定, 依据链 (哪个指标哪条规则), 置信度 (注册时间是近似则降级), 待补数据}。
判定不确定 = 如实标"无法归类" — 不硬塞两架。
