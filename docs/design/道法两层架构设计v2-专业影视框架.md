# 动画产线"道法"两层架构设计 v2 — 专业影视框架

> v1 的升级: 用专业影视的**正式语法体系**替代自创描述。系统性规则, 非个性化补丁。
> 参考: Hollywood storyboard pipeline, Pixar color script, ASC Cinematography Manual

---

## 核心转变: 从"描述"到"规则"

```
v1 (描述式 — 不够专业):
  "这个场景用明亮的光" ← 每次LLM理解的"明亮"可能不同
  "人物穿白衬衫" ← 不是规则, 是一次性的描述
  "不要黑色背景" ← 补丁, 不是体系

v2 (规则式 — 专业):
  Lighting: { key: { source: "window", direction: 135°, temp: 5600K },
              fill: { source: "bounce", ratio: 4:1 },
              type: "motivated_natural" }
  ← 结构化参数, 可校验, 可复现, 机器可执行

  Grammar: { rule: "180_degree", axis: "s01_s02_line" }
  ← 行业标准规则, 可程序化检查

  Coverage: { master: "s01", pattern: "ELS→MS→CU→MLS" }
  ← 专业镜头覆盖模式, 可强制执行
```

## 二、法层: Episode Shooting Script (每集拍摄脚本)

不是"分镜表"(那是术层), 而是**导演给摄影/灯光/剪辑的指令集**。
如同真实片场的 "Director's Notes + DP's Shot Plan + Editor's Cut Notes"。

### 2.3 法层的校验规则 (可程序化执行)

```python
# 这些不是建议, 是硬校验 (如同 prop_lock_audit)

validate_scene_first_shot_is_establishing(scene)    # 首镜必须ELS/LS
validate_adjacent_shot_size_variance(shots)          # 相邻镜景别至少差一级
validate_scene_last_shot_is_wide(scene)             # 末镜必须回远景
validate_lighting_consistency(scene)                # 同场光源/方向/色温一致
validate_eyeline_pairs(shots)                       # 视线方向匹配
validate_prop_visibility(shots, props_in_scene)     # 道具可见性追踪
validate_color_arc_progression(scenes)              # 色彩弧线递进
validate_narration_sync(shots, narration_segments)  # 旁白段落与镜头对齐
validate_transition_types(scene)                    # 转场类型合法
validate_pacing_curve(episode_structure)            # 节奏曲线符合模板
```

## 三、与现有管线的整合点

```
现有流程:
  规划(立意闸) → 切场 → 立意.md → 人工确认 → 分镜续跑 → 增强器 → K2 → H3 → 装配

改造后:
  规划(立意闸)
    ├─ ① 切场(不变)
    ├─ ② 立意.md(不变)
    ├─ ③ [新增] 拍摄脚本生成 (法层)
    │     输入: 道层 + 切场 + 稿件 + 音频manifest
    │     输出: Episode Shooting Script (JSON)
    │     校验: 上述 validate_* 全部通过
    ├─ ④ 人工确认(立意 + 拍摄脚本)
    └─ ⑤ 分镜续跑
          导演LLM 读拍摄脚本的 shot_list 写 keyframe_zh
          每镜 keyframe 必须引用 shot_list 的:
            size / angle / composition / lighting_note / prop_visibility

  增强器 pass1
    读法层 lighting_setup 写光影 (不自由发挥)

  增强器 pass2
    读法层 continuity_notes 写运动/衔接

  K2
    读法层 lighting_setup + 道层 lighting_doctrine
    (光源/方向/色温 结构化注入, 不是自由文字)

  H3
    读法层 blocking + transition_to_next
    (运动方向和衔接方式有据可依)

  装配
    读法层 cut_points + color_arc
    (转场类型和色彩节奏在剪辑层执行)
```

## 四、与现有系统的关系 (不推翻, 只增层)

| 现有组件 | 改动 |
|---|---|
| 圣经 JSON | 扩展为道层完整结构 (增加 grammar_rules, lighting_doctrine, color_script, prop_system, typography) |
| DIRECTOR_SYS | 增加引用法层 shot_list 的指令 |
| _ENHANCE1_SYS | 光影按法层 lighting_setup, 不自由发挥 |
| _ENHANCE2_SYS | 运动按法层 blocking + transition, 不自由发挥 |
| prop_lock | 从法层 prop_visibility 自动生成 |
| K2 build_prompt | 光影参数从法层结构化注入 |
| H3 build_prompt | 运动从法层 blocking + transition 注入 |
| 剪映装配 | 转场从法层 cut_points 注入 |
