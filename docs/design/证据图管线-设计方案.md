# 证据图管线 (evidence_image) · 设计方案

> 定稿 2026-09-04。触发案例: Gemini 3.8 稿 (`projects/20260903_183552_f79dbb`) —— 稿中大量测试/对比数据段 (智能测试 59/62、SWE 基准 73.7、305词/s vs 154、单价对比), 最有说服力的画面是真实榜单/跑分/价格截图, 但成片全是 Pexels 通用空镜。

## 一、问题与根因

1. `url_fetcher.fetch_url` 只抽文本丢图 —— 素材包 31 条 + 原文, 图片 URL = 0
2. 导演层无"证据图" workflow
3. 素材层 2.0 只管官频视频切片, 不管网页图片

**用户裁决**: 全链一次到位, 硬条件 = **只有"有测试、有比较"的段落才配图**; 图片抓取起点 = index.html「🌐 抓取 URL」同行的「📷 搜图」开关 (全链总闸)。

## 二、数据流

```
index.html「🌐 抓取 URL」+「📷 搜图」开关(总闸, 默认开)
   ├─ 抓取时: fetch_url(with_images=True) 顺手提取本页 <img> URL (零额外请求)
   │    → 前端暂存 fetchedImages → 建稿存 articles.images_json (非空 = 总闸开)
   ▼
素材包建包 → 审计完成后 (仅当 article.images_json 非空) 自动扫图
   ├─ 原文条目复用 article.images_json (不重抓); 其余条目逐页 fetch+extract (条目≤20, 每页≤4, 整包≤24)
   ├─ 下载缓存 {materials_dir}/evidence/cache/{sha1(url)[:16]}.{ext} (Pillow 校验: 可解码+宽≥400)
   ├─ 9B VLM 打标 (llama-server 自拉起, 单图→JSON: is_chart/kind/desc_zh/numbers/quality/watermark)
   │    fail-closed: VLM 不可用/超预算(120s/包) → 存 vlm:null 不进池
   ▼ 写回 material_items.images_json
导演规划 (LLM 菜单加 evidence_image) → 代码闸门三道 (可用性/语义/数量≤10) → evidence slots
   ▼
slot 执行: collect_evidence_pool (is_chart ∧ quality≥4 ∧ watermark≠heavy)
   → pick_image_for_slot (数字重合×10 + 关键词×2 + kind 匹配×2, 单图中文读法匹配)
   → ffmpeg 单 pass: 等比+黑边 → zoompan Ken Burns → fade → drawtext 图源角标
   → render_scale_pad 归一化 (30fps+静音轨) → evidence_{idx:03d}.mp4
   ▼
合成 P 线 / 剪映草稿 J 线 自动接轨 (workflow 无关的 video 轨)
```

## 四、关键设计决策

1. **数字中文读法匹配** (最强选图信号): 图上 OCR 出 "73.7", 稿件口播是 "七十三点七" —— 复用 `tts_verify._num_to_reading` 把池图数字转中文读法再子串匹配。单个数字 ("5"→"五") 太泛, 只认阿拉伯独立 token。
2. **语义闸门数字+词集双条件**: 数字字符 ∧ (测试/比较词集 ∨ "比X快/高/贵"句式)。"一样/一下/一般"等"一"字词素先剥离, 否则中文句句有"一"。"比如"不算比较句式。
3. **fail-safe 全链**: JS 渲染页抓不到图→无池→全降级; VLM 挂→vlm:null 不进池→退化现状; 池空/无匹配→RuntimeError→fallback 链 broll_pexels。扫图失败绝不置包 failed。
4. **截图不变形**: 先等比缩放+黑边 pad 再 zoompan (PPT 线直接 zoompan 会拉伸数字)。
5. **版权口径**: 角标+评述性短时使用; 片尾 hf-source-v1 来源卡 (_append_source_slot) 条目级来源双保险。
6. **幂等扫图**: `_has_scan_product` (带 local_path 的条目才跳过) —— add_item 抓取时存的 URL 级 images_json 恰是待扫对象, 不误跳。

## 七、0910 更新 — 新闻线放行 + 出处闸 + 动效节奏修复

**触发**: ① "27岁研究员连辞OpenAI/Anthropic" 稿成片零证据图 (7 张原文截图全被 kind 规则拦); ② 两张裸封面图 (员工声明封面/文章头图) 信服力=自制 HF 卡, 用户裁决不放。

1. **新闻线放行**: 池闸 `kind ∈ {is_chart, photo, screenshot}` (旧规则只收 chart/photo — 按 0905 跑分文设计, 新闻稿全灭); 语义闸门 `_NEWS_KW` (声明/宣布/辞职/公开信/推文/坦言…) 命中即过, 无须数字+比较双条件; `_KIND_SIGNALS` 补 screenshot 通道 (VLM kind 词表对齐)。
2. **has_source 出处闸** (核心): VLM 打标新增 `has_source` 字段 — **true 仅限图上可见发布平台界面元素或机构标识** (社交平台账号头像/用户名/平台UI框架/点赞转发栏、机构 logo/信头、带 URL 页面); ⚠ 文档自带的标题页/署名/日期/人数**不算** (任何人可排版伪造)。池内 `kind=screenshot` 必须 has_source (chart/photo 豁免 — 数据表与实物本身即证据)。`_has_scan_product` 要求标签含 has_source → 旧包补扫一次自动迁移。**语义: 证据图唯一存在理由 = 信服力 > 自家 HF 卡; 平台 UI 是溢价来源, 裸排版没有。**
3. **Ken Burns 动效修复** (`_build_vf`): zoom 不再线性铺满全时长 (文字截图全文只在末帧达成=一闪而过), 改**动画窗口 ~1.2s + 定格收尾态** (全文可读 ≥88% 时长); 缩放前 **2x 上采样**抗 zoompan 整数取整抖动。平移 (实物图) 保留全程缓移。
4. **E2E 实证**: 该稿 4 张 36氪原文推文截图 (Coxon 辞职/立场讨论/呼吁) 入片, 2 张裸封面出局; 池 7→5。
