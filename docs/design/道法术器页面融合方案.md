# 道法术器架构 — 页面融合与升级方案 (v3 附录)

> 2026-10-07 定稿。基于道法术器架构设计v3, 详述与现有页面/按钮/用户流程的融合方案。
> 原则: 不推翻现有页面, 在用户已有习惯的流程中"插入"新能力。

---

## 一、现有用户流程全景

```
用户操作流 (从建书到出片):

books_story.html (讲书页)
  ├─ 步骤1: 输入补全 → [确认1]
  ├─ 步骤2: 评论层+素材 → [确认2]
  ├─ 步骤3: 生成总纲 → [确认3] → 进入逐集
  ├─ 步骤4: 逐集生成稿 → [确认4]
  └─ 步骤5: 进产线
       ├─ → audio.html (TTS音频 → 人耳验收)
       └─ → anim.html (动画工坊)

anim.html (动画工坊) — 核心产线
  ├─ 🧭 规划(立意闸)
  │    ├─ 切场 (六拍模块)
  │    ├─ 立意.md (隐喻/视觉母题/道具锁定)
  │    └─ [人工确认] ← 用户看立意
  ├─ ▶️ 分镜续跑 (逐场分镜 + 增强器)
  ├─ 🎨 K2 批生图
  ├─ ✅ 全部过审
  ├─ 🎬 H3 批生视频
  ├─ 🎚 对齐试算/落盘
  ├─ 🎞 装配剪映草稿
  └─ 每镜可: ♻️ 重规划 / 🎲 重roll / ⏩ 变速

style_bible.html (圣经页) — 风格管理
  ├─ ✨ 生成圣经
  ├─ 🎲 重掷
  ├─ 🎨 圣经试渲
  └─ 💾 保存手调

style_characters.html (角色设计台)
  ├─ 🎲 从各集提炼角色
  ├─ 🖼 全部角色生成定妆照
  ├─ 每角色: 🎲 重roll
  └─ 💾 保存角色卡 (回写圣经)

style_board.html (风格选型板)
  └─ ▶️ 启动选型 (10-20分钟)
```

### 2.3 按钮变化

| 按钮 | 现有 | 变化 |

| **新增** 👁 世界预览 | 无 | 用道参数渲 1 张"世界定妆照"(综合场景) |

| 页面 | 联动 |

## 三、法层融合: anim.html 升级

### 3.1 位置: 在立意和分镜之间

```
现有流程:
  🧭 规划(立意闸)
    → 切场 + 立意.md
    → [人工确认]
  ▶️ 分镜续跑
    → 导演LLM写keyframe_zh (自由发挥)
    → 增强器补光影/氛围

升级后流程:
  🧭 规划(立意+拍摄脚本)
    → 切场 + 立意.md + 拍摄脚本.json  ← 新增
    → [人工确认: 立意面板 + 拍摄脚本面板]

    → 导演LLM只填创作槽 (action/detail/atmosphere)
    → keyframe由法模板+术槽值组装
```

## 四、术层融合: 分镜续跑升级

### 4.1 变化最小 (用户几乎无感知)

```
现有: ▶️ 分镜续跑
  → 后端: LLM 写完整 keyframe_zh
  → 前端: 显示 keyframe 全文

升级后: ▶️ 分镜续跑(按法填空)
  → 后端: LLM 只填 action/detail/atmosphere
  → 后端: 组装函数生成 keyframe_zh
  → 前端: 显示组装后的 keyframe (外观不变)
  → 额外显示: 法层标签(景别/角度/光影/道具)
```

**用户操作习惯完全不变** — 还是点 ▶️ 分镜续跑, 看到的还是每镜的 keyframe, 只是底层生成方式变了(从"LLM 全写"变为"法模板+术填空")。


## 九、风险与缓解

| 风险 | 缓解 |
|---|---|
| 道文档生成质量不达标 | 多次重掷 + 人工逐字段审核 |
| 法层镜头序不合理 | 人工审核面板 + 可手动编辑 |
| 术层填空质量低于现有全写 | 先在ep2做A/B对比(法填空 vs 现有全写) |
| K2组装prompt效果差 | 保留现有路径作为fallback |
| 校验过严阻塞产线 | 校验只做修正不做阻断(除非结构性错误) |
| 用户学习成本 | 界面操作习惯不变, 新增内容渐进展示 |
