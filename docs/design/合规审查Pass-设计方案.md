## 0. 一句话

洗稿产出后、TTS 之前插一道**合规审查 Pass**：确定性词表扫 + LLM 按赛道规则集审查 → 自动修复 + 风险报告人工终审 → 合规稿进后续流程。**我们的独家优势：素材包记录了每个数字的来源 URL，"数据须标来源"这条平台红线可以系统化解决**（豆包都要靠人工补）。

## 1. 风险→系统能力映射（豆包五条逐条）

| # | 豆包风险点 | 系统化方案 | 层 |
|---|---|---|---|
| 1 | 情绪化标签词"拜鬼"（高频拦截词）、"修罗场" | **确定性替换词表**（拜鬼→参拜靖国神社）+ LLM 改写强判词 | R1 词表层 |
| 2 | 时政数据无来源标注（网信重点整治） | **素材包来源映射**：洗稿引用素材包数据时自动带口播来源（"据共同社报道"）；CR 扫描裸数字报风险 | R2 来源层（独家优势） |
| 3 | 主体泛化（"日本"一棍子） | 洗稿 prompt 规则：**区分"日本右翼政客/日本政府"与"日本民众"**；CR 审查泛化句 | R3 口径层 |
| 4 | "点赞给官方机构/外国政客"话术 | **话术黑名单**（点赞给X→客观评价句式），boost 结尾体系同步约束 | R1 词表层 |
| 5 | 时间线/事实错误（直接下架级） | **事实核对 Pass**：稿件中的数字/日期 ↔ 素材包证据交叉验证（确定性匹配），不符报高危 | R4 事实层 |

## 2. 架构

```
七层洗稿(laotan-geo) → boost P4精修 → 【CR-Pass 合规审查】→ P5情绪 → TTS → ...
                                     │
                ┌────────────────────┼────────────────────┐
                │ ① 确定性扫描(毫秒级)                      │
                │   词表替换/话术黑名单/裸数字检测/主体泛化正则 │
                │ ② LLM 审查(DeepSeek, 结构化输出)           │
                │   赛道规则集 + 口径对齐; 输出风险条目        │
                │   {quote, type, severity, fix, reason}    │
                │ ③ 修复                                    │
                │   确定性→自动替换(等长优先, 保 P4 字数档)     │
                │   LLM→局部句重写(只改风险句)                │
                │ ④ 报告 → writing.html 合规面板人工终审       │
                │   逐条 应用/忽略; 存 script.compliance_json  │
                └──────────────────────────────────────────┘
```

## 3. 赛道规则库 `config/compliance_geo.txt`（首发种子，从豆包评估直接提炼）

**词表替换（自动执行）**：
- 拜鬼 → 参拜靖国神社（本稿出现 6+ 次）
- 修罗场 → 深刻分歧 / 最真实的撕裂现场
- 自寻死路 → 面临重大风险

**话术黑名单（LLM 改写）**：
- "点赞给〔官方机构/外国政客/群体〕" → 客观评价句（例：点赞给鸠山由纪夫 → 鸠山由纪夫是日本政坛少数敢于直面历史、公开反省谢罪的政客）

**口径规则（洗稿 prompt + CR 双层）**：
- 批判主体 = 日本右翼政客/日本政府/防卫省，**永不泛化"日本/日本人"**
- 区分日本右翼与日本民众（必要时主动点出"日本老百姓的养老医疗也在为军费让路"——本稿已有，是加分项）
- 立场与我方外交表态口径对齐（严正交涉/点名谴责 可用客观转述）
- 时政金句允许观点锐度，禁止煽动性判词（"嘴上喊和平的国家算盘最响"→"部分嘴上高喊和平的日本右翼政客，背后却在大力推进军备扩张"）

**来源规则**：
- 引用素材包数据 → 口播自然带源（据共同社报道/日本防卫省申请数据显示）
- 无来源裸数字 → CR 高危提示（提供素材包内匹配建议或人工补）

**事实核对**：
- 稿件数字/日期 ↔ 素材包 raw_text 确定性匹配；匹配不到 → 高危报告（防 LLM 幻觉数字——七层洗稿本来就禁编造，这里是最后一道网）

## 4. 发布检查单（CR 产出物之一，不入流水线）

豆包实操建议直接模板化：标题客观化 / 画面用新闻资料图不用血腥历史画面 / 审核中过久或 0 播放=触发复审需回稿 / **时政内容不投 DOU+/千川**。

## 5. 分阶段实施

### 5.0 CR-0.5 地缘提示词优化循环（2026-08-16 启动，用户设计）

**机制**：豆包当外部合规裁判，批量成稿→逐篇点评→提示词迭代，不跑全产线（到成稿即停）。

```
用户收集地缘新闻 .txt → data/geo_batch/in/
  → python scripts/geo_batch_review.py        (批量洗稿, laotan-geo CR-0 版)
  → data/geo_batch/out/批次N/ 生成 成稿.txt + 豆包点评.txt(内嵌固定评估指令)
  → 用户逐篇喂豆包(整段复制, 指令+成稿一起) → 回复粘回点评文件
  → AI 汇总本批点评 → 提炼新规则入 laotan-geo.txt → git 即版本记录
  → 下一批 (提示词已迭代)
```

**可比性关键**：每篇用同一段固定评估指令（七维度+风险等级），点评口径一致才能跨批次对比提示词版本效果。简化说明：本循环不含解构/素材包注入，主要考察模板层的合规行为（词表/句式/泛化/来源意识）。


| 阶段 | 内容 | 成本 | 效果 |
|---|---|---|---|
| **CR-0（立即可用，零代码）** | 本文档 §3 规则写进 `laotan-geo.txt` 洗稿 prompt（地缘合规五条）+ 洗稿时素材来源口播规则 | 改一个提示词 | 产出端先避 80% 坑 |
| **CR-1** | CR-Pass 服务：确定性扫描 + LLM 审查 + compliance_json + writing 页合规面板（逐条应用/忽略） | 1 个服务 + 1 个面板 | 全赛道可复用，tech/财经 轻量规则集 |
| **CR-2** | 来源自动标注（素材包 per-item source→稿件数字溯源）、事实核对 Pass、发布检查单生成 | 中 | 独家能力成型 |
