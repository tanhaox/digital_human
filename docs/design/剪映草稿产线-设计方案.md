## 0. 一句话

剪映草稿 = 一个文件夹（`draft_content.json` + 素材）；pyJianYingDraft 已把它代码化（几百个官方特效枚举 + 模板替换 API + 批量导出）；把"导演 slot 时间轴"直接写成草稿轨道，**特效模板固化为 J 线，渲染出口交给剪映**，人工在剪映里做最后的精修与导出（正好吸收现有"BGM 手动在剪映调"的习惯）。

## 2. 调查记录：pyJianYingDraft 能力边界（v0.3.0，本地 `_ref_pyJianYingDraft/`）

### 2.1 草稿能装什么（全部代码可生成）

| 类别 | 能力 |
|---|---|
| 素材 | 本地视频/图片/音频 + 时间截取 + 变速 |
| 视频处理 | 关键帧、蒙版、色度抠像、背景填充、混合模式、整体调节 |
| 特效 | **片段动画（入场/出场/组合）、片段特效、滤镜、独立轨道特效/滤镜、转场** |
| 文本 | 样式/描边/背景/阴影、花字、气泡、文本动画、SRT 字幕导入 |
| 贴纸 | 贴纸 + 贴纸关键帧 |
| 音频 | 淡入淡出、音量、场景音、音色效果 |

特效的"原料库"是现成的：`pyJianYingDraft/metadata/` 内置**几百个官方特效枚举**（每个带资源 ID + 可调参数范围），剪映打开草稿时自动下载未缓存特效（5.9 上可能超时，需预热）。

### 2.2 模板模式（= 本方案核心机制）

```python
draft_folder = DraftFolder(r"<剪映草稿目录>")
script = draft_folder.load_draft_record("模板名")  # 加载剪映里做好的模板草稿
script.replace_material_by_name(...)   # 按素材名替换音视频素材
script.replace_text(...)                # 替换文本内容（自动重算样式区间）
script.import_track(...)                # 把模板中的整条轨道导入新草稿
script.dump("新草稿名")                  # 另存
```

与 HF 产线完全同构：

| | HF 线 | 剪映 J 线 |
|---|---|---|
| 模板 | `template_library`（HTML） | 剪映里制作的草稿文件夹 |
| 填充 | `template_filler`（占位符替换） | `replace_material / replace_text / import_track` |
| 渲染 | headless Chrome 截帧 | 剪映打开 → 导出 |

### 2.3 硬约束（2026-08-15 四连实验后定稿）

**写入路径实验记录**（学习25期为样本，详见 [剪映模板拆解-学习25期-抖音是小鼎呀.md](../teardown/剪映模板拆解-学习25期-抖音是小鼎呀.md)）：

| 实验 | 假设 | 结果 |
|---|---|---|
| 01 | 改顶层明文 template.json + subdraft → 剪映导入时带上改动 | ❌ 剪映只认加密 `draft_content.json`（可自行解密），明文改动全被无视 |
| 02 | 剥离加密文件逼明文回退 | ❌ 草稿不被注册发现（发现机制依赖 draft_content.json 存在） |
| 03 | 改已导入草稿的 `Timelines/*/template.json`（剪映自己写的明文） | ❌ 每次打开从加密文件重建，Timelines 只是导出缓存（只写不读） |
| **A** | **pyJianYingDraft 从零生成明文草稿 → 新版剪映打开** | ✅ **成功**：图+音+字+动画三轨草稿正常打开（30s 样片） |

**结论（修正后的硬约束）**：
1. **新版剪映"打开时接受明文、保存时才加密"**——代码生成的明文 `draft_content.json` 完全可用，J 线在当前新版剪映上直接成立，**无需旧版导出机**（除非要全自动批量导出，那仍需 ≤6.8）
2. **改"别人做的/剪映保存过的"加密草稿 = 死路**（除非上 AES 解密工具，本地有 `crypto_key_store.dat` 钥匙文件，社区工具有先例——暂不做，Y 线需求出现再说）
3. 外购模板的正确用法 = **结构参考库**：从明文快照（`data/jy_template_snapshot/`）提取时间轴结构/特效 ID/动画 ID/贴纸 ID，由代码**从零生成**等价草稿，而不是在原模板上替换
4. 附带发现：草稿列表按 `root_meta_info.json` 注册 + 修改时间排序，外部塞入的草稿要 bump 时间戳才会出现在列表顶部

## 3. 调查记录：剪映模板生态（模板从哪来）

### 3.1 模板的物理形态

电脑专业版的"模板"本质 = **草稿文件夹**（`draft_content.json` + `assets/` 素材）。使用方法：解压 → 放入 `JianyingPro/Drafts` 目录 → 重启剪映即在草稿列表出现。**这与 pyJianYingDraft 模板模式的输入完全一致**——外部获得的模板可以直接进我们的代码管线。

⚠️ 手机版"剪同款"模板是服务端渲染的，**拿不到草稿文件**，不在本方案范围内。

### 3.2 外部获取渠道（丰富度足够）

| 渠道 | 形态 | 说明 |
|---|---|---|
| 爱给网 aigei.com | 剪映模板/剪辑草稿/转场/滤镜 | 免费量大 |
| 潮点视频 shipin520.com | 6666+ 剪映素材 + AE 模板 | 部分收费 |
| 觅知网 51miz.com / 摄图网 699pic.com / 光厂 VJshi | 视频模板 | 授权制，商用需会员 |
| 稿定设计 gaoding.com | 10000+ 卡点模板，在线一键替换 | 在线编辑为主 |
| **淘宝** | 打包草稿合集（0.01~几十元） | 商家发压缩包/网盘，导入方式同上；也有素材站 VIP 代充 |

### 3.3 外购模板的三个验证点（J1 前必须实测）

> **实测工具已备**：`scripts/_inspect_jy_template.py <模板包目录> [--deep]` — 自动扫全包 draft_content.json + template.json 明文镜像，输出加密与否/素材完整性/命名规律。

### 3.3.0 🔥 实测结果（2026-08-15，淘宝学习期模板包 45 草稿）

> **25期完整拆解见 [剪映模板拆解-学习25期-抖音是小鼎呀.md](../teardown/剪映模板拆解-学习25期-抖音是小鼎呀.md)**；明文工作副本快照在 `data/jy_template_snapshot/`（847 文件/32 草稿）。

**关键发现：新版剪映草稿目录里有明文镜像 `template.json`**——`draft_content.json` 虽加密（AES），但同目录 `template.json` 是**完整明文时间轴**（version 360000），包含：

- 全部轨道（video/text/effect/sticker/audio/adjust）与片段
- materials 全量：videos/audios/texts/**effects/transitions/stickers/material_animations(入场出场动画)/**
- **`beats`（音乐踩点数组）**——卡点模板的节奏点直接可读
- **`materials.drafts`（复合片段=嵌套子时间轴）**——多层嵌套结构完整保留
- 文本内容为 JSON-in-JSON（text + styles 数组，样式逐字可控）

实测 45 草稿：**19/45 有 template.json 明文镜像且正好覆盖模板包主体**（学习 12~29 期全套）；其余 26 个（用户自建 8月xx日 + 少数学习期）无镜像、全加密。

三个验证点的答案：
1. **加密与否** → content 全加密，但**template.json 旁路绕过**，无需解密/旧版
2. **素材完整性** → 部分缺失（学习21期缺 26 个引用，可能是"我的预设"类服务器端资源）
3. **可替换性** → 素材名有 `material_name`（如"复古电视机"/"复合片段15"），文本逐字可定位——**`replace_material_by_name` / `replace_text` 的匹配锚点齐全**

**待验证（J1 首个实验）**：剪映打开草稿时**读不读 template.json**（即改了它能不能生效）——若只读不写，则它是只读快照，我们改完需另想办法让剪映重新加载；若可写生效，J 线在**当前新版剪映上直接成立**，连旧版导出机都可以不装。

### 3.3.1 版本兼容矩阵 + 改版（破解版）结论（2026-08-15 讨论定）

| 模板包制作版本 | 旧版/改版剪映（5.9/6.x 基底） | 新版剪映（7+） |
|---|---|---|
| 老版本制作（多数淘宝包） | ✅ 完美：明文 JSON，代码可直接解析 | ⚠️ 能打开，但**保存即转新版格式+加密**，源文件就废了 |
| 新版制作（7+） | ❌ 打不开（"由更新版本创建"+加密） | ✅ 正常 |
| 代码生成的新草稿（明文） | ✅ | ⚠️ 同上，别用新版保存 |

**结论**：① "改版（旧版破解）+ 淘宝老模板包"是兼容组合；② 破解锁对模板包零影响，解锁的是渲染时 VIP 特效/去水印——§3.4 的免费枚举限制可放开；③ 操作纪律：
- 模板包到手**只读备份**，永远在副本上编辑（任何剪映保存都会改写格式，明文源丢了回不来）
- 导出机（旧版/破解版）与日常剪映**物理隔离**，新版不碰草稿目录
- 破解版装隔离环境，不登录主力账号；商用合规风险矩阵化放量前评估

### 3.4 免费特效 vs 会员特效（"剪映比较恶心"的部分）

pyJianYingDraft 的特效枚举带 `is_VIP` 标记（如 `_1998` 为 False 即免费）。**策略：J 线只用免费特效枚举**，会员特效（文字/贴纸/部分转场）不用或替换近似免费款——避免产线绑定会员账号。

## 4. 整体规划（2026-08-15 与用户对齐：先规划后动手）

### 4.1 产线规划：J 线进系统（三处接入点）

```
                        ┌─────────────── 素材执行层（不动） ───────────────┐
口播稿 → TTS分段 ──► 导演规划 slot ──► 执行：P线(broll/Pexels) / HF线(卡片) / C线(DHV) / ...
                        │                  ▲
                        │                  └─【接入点②】slot 新增 effect_recipe 字段
                        │                     （R1~R8 配方，由段落情绪/功能自动建议）
                        ▼
                ┌─── 成片出口层（二选一，按 job 配置） ───┐
                │ A. composition_service (ffmpeg) → 成片.mp4（保留，全自动兜底）
                │ B. jy_draft_service → 剪映草稿【接入点①，J1】
                │      video轨=slot素材 + audio轨=TTS wav + text轨=SRT + 特效/动画/贴纸
                └──────────────────────────────────────────┘
                        ▼
                【接入点③】草稿直接落剪映草稿文件夹（§4.2），人工审+BGM+导出
```

- **接入点①（出口）**：`jy_draft_service` 与 `composition_service` 并列，导演台"一键成片"旁加"导出剪映草稿"；slot 时间轴直接映射草稿轨道（微秒制，source/target 双坐标系，实验 A 已验证通路）
- **接入点②（效果）**：导演规划的 slot 加 `effect_recipe` 字段——J 线不只是"搬运工"，每个 slot 都带效果配方（字幕浮现/强调/晃动/标注），这就是 J 线相对 ffmpeg 合成的增值
- **接入点③（素材类型）**：远期 slot 可直接引用 `jy_effect_library` 纯特效段（开场/转场包装），与 broll/hf_card 平级
- **C 线/DHV 的位置**：数字人出镜素材照旧产出 mp4，进 J 线时就是普通 video 轨素材 + 美颜组配方挂上
- `composition_service` 保留为全自动兜底出口；J 线是"可编辑+带特效"的优选出口

### 4.2 导出流程：不再导出合成视频，导出草稿进剪映文件夹

**目标流程**（J1 稳定后成为默认出口）：

```
导演台点「导出剪映草稿」
  → jy_draft_service 生成完整草稿文件夹（三轨+效果配方）
  → 直接落 C:\Users\<user>\AppData\Local\JianyingPro\User Data\Projects\com.lveditor.draft\
  → 注册 root_meta_info.json + 时间戳置顶（实验已验证此机制，外部草稿不 bump 时间戳会沉底）
  → 用户打开剪映 → 草稿在列表顶部 → 审片/调 BGM → 导出成片
```

要点：
- **音画不预合成**：TTS 分段 wav 全量进 audio 轨（不是聚合后的单文件），段落级可再调；slot 素材各自独立进 video 轨
- **BGM 留人工**（现状习惯），远期可加"推荐 BGM 轨（音量 0.2/循环/3s 淡出）"预挂不预混
- 草稿命名规范：`DH_{日期}_{文章ID}_{人设}`，与 projects 目录对应，可在剪映里溯源
- 同一 job 可反复重导出（allow_replace），改稿→重跑→再导草稿，循环无损
- ffmpeg 合成出口保留开关（矩阵放量后无人值守场景用）

### 4.3 模板研究：长期磨合轨道（与开发并行，不阻塞）

**认知（用户口径）**：每个特效/动效出现在什么位置、怎么配合画面与语义，需要大量研究磨合——开放库（pyJianYingDraft 元数据 + catalog）只是原料，"效果↔语义"的匹配是慢功夫。

**研究机制（效果研究循环）**：

```
看片拆解（模板/对标视频）
   → 提炼配方（效果组合+位置规律+时长）入库 jy_effect_catalog
   → jy_draft_service 上片（真实稿子套配方出草稿）
   → 剪映人工审 + 导出 + 投放
   → 数据回流（完播/跳出章节定位）→ 修正配方 → 循环
```

- **起步策略**：先全量套通用配方（R1 字幕/R3 人像/R5 讲述——低风险高频共识），特殊效果（故障/水墨/错峰贴纸）逐个研究、逐个上
- **配方可回滚**：每个配方独立 ID+版本，A/B 由导演 slot 的 effect_recipe 字段控制，投放数据说话（复用现有爆品改造的数据回流思路）
- **悬案清单**：`7416258989467374091`（×180 高频特效）等未对号 ID，剪映里逐个点开补录名字与视觉
- **快照资产**：`data/jy_template_snapshot/`（32 草稿）是研究原料库，新模板到手先进快照再研究

## 9. HF 卡上字幕配色 (2026-09-10)

- **色**: HF 文字卡窗 (`_HF_TEXT_FAMILIES`) 内字幕切 **#465773** 深蓝灰 (subtitle_style `_SUBTITLE_COLOR_HF` + `_StyledTextSegment(base_color=)`); 窗外照旧奶油 #F9F3C4。实锤: 纸墨系卡底与奶油色太近, 字看不清。
- **高亮**: HF 窗内**去金色划重点**单色化 (卡面文字已带强调, 字幕再高亮=打架); P 线 (broll/证据图) 金高亮照旧。job_draft 字幕构造按 chunk 时间窗与 hf_windows 判交。
- **hf_title 大小字硬闸** (hf.py): title 4~12 字 ∧ kicker ≤16 字, 违规 RuntimeError → fallback 链降级 broll。起因: LLM 4/7 漏给 render_config, 口播自动提取把整句塞卡面 (title=句子碎片/kicker=27字长句)。
