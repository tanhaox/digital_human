## 一、核心原则（四条）

1. **每层独立目标**——不是"在上一层上继续加工"，是剧组部门制：每个部门有自己完整的目标/交付物/验收闸。否则拆层只是把一把梭哈切成几把小梭哈。
2. **最小输入契约**——每层 LLM 只见本层目标所需的最小上下文（分镜只见卡名不见 look 全文；布景师不见运镜）。梭哈从输入端根除。
3. **代码装配**——层与层之间全是确定性管道，LLM 层间不传全文只传契约。K2 prompt = f(画面句, 选角单, 布景圣经)，代码拼接。
4. **冲突裁决序**——独立目标会打架，裁决序明文由代码执法：**布景锚 > 画面句几何词 > 群演词**。

## 四、三问结论（1107 讨论定谳，章程的种子）

1. **一镜塞多镜头**：动作分段=beats 机制现成（`From X to Y` 时间轴指导）；机位切换=i2v 无剪辑点做不到。合并镜=**用时长换一致性**（一次生成内车/人/景天然同一），代价=一镜一构图+长镜尾段衰减需实测。
2. **同弧统一关键词**：能解决大半——关键词是"收窄分布"非"像素锁定"（v2 实证：一致性靠关键词锚）。
3. **角色卡+参考图**：圣经卡已有（含"下巴光洁无胡须"粒度 look）；卡名写对→⑧ 路由自动走 r2v 带定妆照=防漂移生效。**参考图扛身份→文本省 look 长描述=关键词稠密度天然稀释**（r2v 架构思想）。推论：③ 导演稿→生道具/场景定妆照入库=远期批4。

## 九、分镜字段表 v2（1107 官方结构定稿，③ 交付物 schema）

> 用户拍板（1107"这个升级特别棒"）。三方对表合并：BFL 官方提示词指南 × Krea 2 官方文档（**我们 K2 引擎的官方库**）× 产线三特化（卡引用/光归布景/无运镜字段）。
> 官方源存档：`.tmp/bfl_building.md` / `bfl_json.md` / `bfl_camera.md` / `krea_expansion.txt`（1107 拉取）。

### 9.1 两条官方裁决

1. **清单 vs 散文，官方答案 = 分层都用**：BFL 官方 JSON 结构化提示法（[JSON Structured Prompting](https://docs.bfl.ml/guides/usecases_t2i_json_prompting.md)）明定适用场景四条——产线一致结构 / 程序化生成 / 多主体复杂场景 / **独立迭代单个元素**（第四条=我们的重掷经济学）。但 Krea 官方（我们引擎）偏好自然语言长提示。**调和 = 代码装配**：LLM 只填字段表（中间表示），代码装配成 Krea 风格散文段。BFL 官方确认两格式等价（"include the JSON directly, or flatten it into natural language"）。
2. **画面句零运镜获官方背书**：BFL 视频镜头词表 FAQ 原话——一个景别词 + 一个运动词 + 一个清晰主体动作；单句塞太多镜头指令镜头反而不可读。我们更彻底：**字段表无运镜字段**，movement 全归④摄影（CAM_EXEC），散文时代"执法查违建"变结构化时代"图纸上没有这个房间"。

### 9.3 K2 装配模板（字段 → Krea 散文，五段语序对齐 BFL 官方 + Krea 20 例风格）

1. **开场句** = shot_size + camera_angle + lens_dof + 媒介/风格（style_palette 注入）
2. **主体句** = subjects 逐个成组：卡 look 展开 + action_pose + position（主体与属性动作同句——Krea 官方 expansion 规则2）
3. **场景句** = scene_anchor 定型词展开 + composition 三层
4. **光句** = light 弧级注入（LLM 从未手填）
5. **收尾** = extras 群演词 + props 展开词 + mood

执法要点：装配后散文对齐 Krea 官方长描述风格；**Faithfulness First**（Krea 官方规则1——不添加字段外对象）；已详细的输入轻抛光不重扩（规则7）。

**视角一致性（1107 真渲两发实锤，一镜两车）**：① 机位唯一——composition 三层必须出自同一机位（shot_size + camera_angle 定的那个）。② **尺度排他**——shot_size 决定主体层级：medium 及更紧景别里，载具/大物件不得以完整形态二次出现（两发实锤：首渲"车内拍人+车头悬崖"两视角打架、二发 medium 塞整车全景，模型分别和解成"窗外多一辆车"和"透明车+实体车"）；要人+载具+环境关系必须 wide，人降为车窗内剪影。③ 同镜实体第二次出现指代绑定（his / the same），禁止全称再引入——全称=模型眼里新实体。④ **禁否定词**——`no guardrail` 类否定描述实测反而召来护栏（t2i 经典坑：否定=引入），装配句只正面描述存在物。四条均进③验收闸（装配后散文机位词唯一性+景别-实体层级+否定词扫描）。

**beats 光权归零（1107 H3 真渲实锤，白天→黄昏）**：④ 导演 beats 禁写光/时间演化词（sun sinks / light deepens / dusk falls / sky darkens 族）——实测一拍 `sun sinks behind the ridges` 被 i2v 演绎成 6 秒内白天→黄昏的时间跳跃（模型把拍点当全局环境演化执行，光一变=观众读作时间快进，主体动势全被吞）。光的所有权=弧级单点：布景圣经 light 注入 K2 首帧，i2v 锚定首帧光全程保持。这是 9.2 表 light 字段"LLM 不填"在表演层的对称执法——字段不填 + beats 不写，两头掐死。进④验收闸（beats validator 加光词扫描）。

**首帧动势律（1107 H3 真渲实锤，零动势）**：静止首帧 + 静止 beats = 6 秒全静止，弧主旨（"坠崖越狠"）不执行。i2v 忠实延续首帧——**动势必须从首帧带进来**：K2 装配句动作位=动作的冻结瞬间（急刹悬停：车头探出崖缘+白烟+碎石四溅，非"停在路边"）；beats 从该瞬间**向前延续**（最后半米滑移→悬停颤动），不从静止环境微观起手（碎石滚落/雾流动这类替身表演救不回主体钉死）。K2 帧位与④拍表是同一动作的两个时相，装配前对时相。

### 9.4 对批序的影响

- **批1 选角**：subjects[].card 格式即选角单格式（卡名枚举 = 圣经卡；群演走 extras 不占卡位）。
- **批2 布景**：light / scene_anchor / props 三字段归属布景圣经，弧级统一注入（治车/山路/光照三坑的字段位）。
- **批3 表演**：subjects[].action_pose 是④导演 beats 的上游输入。
- ③ 验收闸升级：散文文字质检 → 字段级执法（枚举校验/卡名校验/引用存在性；运镜免查）。
