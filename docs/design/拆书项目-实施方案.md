## 3. 创作编排（生成结构，2026-08-19 讨论定稿）

用户定的 5 步 pipeline（评论层/素材前置为主纲输入）+ 完善：

```
0. POST /books            书名/作者（最小输入）
1. 输入补全 (flash)        知识库补全输入清单            →【确认1】表格确认
2. 评论层书化 (flash)      读者反应清单(痛点/质疑/共鸣/好奇/唱反调)  ┐ 并行
3. 素材包书化 (flash+搜索)  作者背景/书评/延伸报道 聚合+审计        ┘ → 轻确认(默认采纳可改)
4. 多集总纲 (pro)          6集路线图 + 自检(概念/金句/案例覆盖溯源) →【确认2】
5. 逐集生成 (pro)          上下文包=全量输入+评论层+素材精华+总纲
                           +coverage<N+上集尾部(220-目标秒)         →【确认3 每集】
                           确认→写 coverage→可进后半段
```

**已定决策**：
- 确认节点：每集确认（中盘步骤 2/3 轻确认，默认采纳、提供修改入口）
- 重跑：**总是级联**——重跑第 N 集作废 N..6 按序重生成，确认节点仍每集
- 弹性标签：六段结构（钩子/回顾引入/拆解×3/总结预告）按目标时长等比缩放；
  目标时长按书可配（默认 600s，满足 5min+）；字数 2700-3000 保留；
  parser 用 `【\d+-\d+秒｜标签】` 正则识别弹性标签
- 模型分工：补全/评论层/素材检索=flash；总纲/逐集稿=pro
- 人设口吻：创作 LLM 保持中性约束；身份段/结尾在 book_service 后处理注入（生成结构定稿后细化）

**完善点（对用户 5 步基础的增量）**：
- 步骤 2/3 互不依赖 → 并行省时间
- 步骤 4 总纲加覆盖溯源自检（关键概念/金句/案例必须在总纲有落点）
- 步骤 5 每集确认时附自检：与总纲行一致 + coverage 无重叠 + 承上咬合上集尾部

## 3.1 来源与防幻觉（2026-08-19 讨论定稿）

原则：**系统永不要求全书原文**；按手里有什么分级降级，任何档都出片。

来源栈（人工成本递增，全接受）：
1. 精华库：book_source_dir 扫目录（`G:\Desktop\畅销书\` 类，文件名=书名），日常主力
2. 粘贴/上传收件箱：章节/摘录任意来源，系统只收件不问出处（人工编辑行为）；**txt+epub 同目录自动识别**（epub 标准库 zipfile 拆解，非扫描版零 OCR；全书 >10 万字按 epub 自然章节分章提取）
3. 自动搜 L1：官方试读/出版社书摘/作者公开访谈演讲/媒体书评（复用 zhipu_search+url_fetcher）
4. L2+佐证：LLM 记忆+搜索交叉印证（畅销书快路径）

降级矩阵：核心主张/概念——①②锚点、③④L2+佐证(④加人确认)；逐字金句——仅①精华引号句/②摘录/③L1 逐字出处可挂引号，④一律转述不挂引号；案例数据——①②可用，③L1 无则标"待补"，④转述或标注。

硬规则：
- 扩写边界：观点/结论须可追溯来源；场景/类比/解读允许创作（60% 配额），定位明确不算幻觉
- _trace：总纲/逐集每个核心论点带来源档级标签，无标签不入总纲
- 系统不建灰站自动抓取通道（版权红线）；②收件箱出处中立
