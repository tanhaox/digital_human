# 账本体系设计方案 (2026-09-10 立)

> 挎斗 (sidecar) 是通用机制, 不是单份文件: 每个子系统一本账, 记"我们为什么这么改";
> 复盘账本记"世界实际怎么回应"。账本配齐后才能做排除法归因 (多因素系统单账本永对不齐)。
> 动机 (用户令 0910): 改系统要有依据, 不单凭感觉或 bug。

> 【总纲】三条真锚 (0911 用户定谳, 本体系的认识论基础):
> 别人的存活样本 + 别人的爆款样本 + 自己的真实数据 = 三条真锚;
> LLM 公式 = 从"依据"降级为"初始假设"。保留区: TTS纠音/合规词表 (工程/平台事实)。
## 一、账本家族 (已立 + 占位)

| 账本 | 记什么 | 状态 |
|---|---|---|
| **文案挎斗** | 生成/评分/改稿模板的每条规则: WHY/来源案例/验证/退休条件 | ✅ 首本 (laotan-book.rules.md) |
| **复盘账本** | 每条发布视频的真实数据 + 本期变更项清单 | ✅ 模板已立 |
| 视频挎斗 (占位) | 画面模板/页单/证据图/蒙版等视觉决策的账 | 待画面线稳定后立 |
| 音色挎斗 (占位) | TTS 引擎/参考音/情感配方/duration 等决策的账 | 待 2.5 线稳定后立 |
| 选题挎斗 (占位) | 选题类型/赛道/发布时间的决策与效果 | 待数据量起后立 |
| 账号阶段挎斗 (占位) | 账号养号期/破圈期/变现期策略变更 | 待阶段切换时立 |

## 二、通用账目格式 (所有挎斗共用)

```yaml
条目: <规则/决策/配方的一句概括>
WHY: <它纠正什么默认行为 / 解决什么问题>
来源案例: <哪次翻车/哪个数据催生 — 日期+集数/工单>
验证方式: <怎么知道它还在生效 (评审维度/黄金集/金丝雀)>
retire_when: <什么可观测条件满足后可退役>
关联: <与其他账目的耦合 (文案↔画面↔音色)>
```

铁律:
1. 账本是**人看的维护档案**, 永不进提示词串 (0909 审计同源)
2. 规则本体与账本靠**规则文本前几字**对照, 不用 ID 污染提示词
3. **加规则必须同时记账** (没账的规则 = 无出生证明, 审计时按"可删"处理)
4. retire_when 满足 → 黄金集跑"移除实验" → 分数不掉 → 人工批准退役

## 三、排除法归因 (账本配齐后的玩法)

复盘账本每条必填「本期变更项」(相对上条发布: 文案模板版本/画面/音色/选题类型/账号阶段, 哪些变了)。归因规则:

- 只有文案账本变 + 完播掉 → 文案层排查
- 多本同时变 + 结果好/坏 → 无法归因, 下次单变量 (教训记账)
- 全没变 + 结果波动 → 算法/外部因素, 不动系统

## 四、季度审计流程

① 自动扫 retire_when 候选 → ② 黄金集移除实验 → ③ 灰度 3~5 集 → ④ 人工批准退役。
重构触发线照旧: 补丁 >12 / 同条目补 ≥3 次 / 加一须删二。

## 五、与三环螺旋的关系

环① (单稿评分改稿) 产数据 → 环② (元评审, 每5集) 提模板补丁 → **记账进挎斗** →
环③ (真实复盘) 校准评分框架 → **框架修订也记账**。
收敛信号: 改稿 delta→0 且 评分与真实完播相关性稳定 = 文案层榨干, 换工具箱 (选题/画面/微调)。
