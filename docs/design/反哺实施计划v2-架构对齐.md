> 2026-09-27 · 前置文档：[漫剧skill整合与产线差距分析.md](漫剧skill整合与产线差距分析.md)（v1，P1-A prompt_gate 已落地）。
> v2 目的：用户令"反哺前摸清架构，优化合理架构，确保每个流程节点都在提高，完善后再动作"——本文档是全部反哺项的施工图，**拍板后才动手**。

## 〇、v1→v2 的方法论升级

v1 按能力差距排了 P1~P3 清单并直接落了 P1-A。v2 补上三件 v1 缺的事：

1. **架构基线**：把相位状态机、闸门时序、失效传播摸成全图（本轮逐文件亲证），每个反哺项的挂点都有 file:line 依据，不再凭能力矩阵想当然；
2. **冲突预检**：每项写清"与既有闸门的关系 + 不降级论证"——v1 的风险是"第一步 prompt_gate 做好了，P2-A 改 workflow 时把 2ST 最爱配方的质量基线动坏了"这类跨步互毁；
3. **升级判据前置**：所有观察闸（prompt_gate / video_qc）定好"什么数据条件下升硬闸/调整/回滚"，避免观察模式永远观察或过早升闸误伤。

## 一、产线架构基线（反哺挂点相关事实，均已亲证）

### 1.1 相位与单镜状态机

- 相位：`("plan","replan","redo","k2","h3","brand")`（[anim_service.py:38](../../app/services/anim_service.py#L38)），主线 = 音频验收 → plan → k2 → **[人检过审]** → h3 → 装配（同步端点，非相位）。持久层 = shots.json（逐镜原子落盘，job 是内存的，重启重算续跑）。
- 单镜 5 态：`planned → img_done → approved → anim_done`（旁路 `anim_fail`，[shots.py:27](../../app/services/anim_pipeline/shots.py#L27)）。k2 只吃 planned（[k2.py:399](../../app/services/anim_pipeline/k2.py#L399)），h3 只吃 approved（[h3.py:263](../../app/services/anim_pipeline/h3.py#L263)），approve 只认 img_done（[anim_service.py:624](../../app/services/anim_service.py#L624)）。
- `transition()` 只查合法性不设迁移边——**新增状态需同步改 STATUSES + k2/h3/approve 三处过滤器**。

### 1.2 全链闸门时序（浓缩；[人]=人检硬闸，[闸]=代码硬闸，[观]=观察闸）

```
口播稿 → TTS → [人]🎧人耳验收 → [闸]风格绑定挡板 →
PLAN: 句级表 → 切场立意 → [人]📜立意人闸 → 逐场分镜+特区槽位+归真+巡检 →
      [闸]validate_doc硬校验/软警告 → [闸·失效]strip_media → enhance 两级
K2:   [闸]GPU锁 → [闸]timeline_violations → [闸]政治禁区(auto_fix→flag跳卡) →
      逐镜: _scene_eff确定性拼装 → [观]prompt_gate(0927新) → render_gated:
      [闸]VLM守门(永远先跑) → [闸]OCR检字 → 软脏重掷×1 → 硬违禁绝不落盘 →
      text_suspect交人检 → [人]🔍K2图过审(img_done→approved)
H3:   [闸]同K2三闸 → 孤儿回收 → 逐镜: [闸]beats=槽拉齐 → I2V(软硬双超时) →
      gen_narr_sha指纹 → anim_done ✦此处之后零画面级检查✦
装配:  [闸]骨架场无镜拦 → 素材解析(真片>静图>占位卡) → 字幕/音效/开场套件 →
      [软]gen_narr_sha错配审计(只亮灯不拦) → 剪映草稿
```

### 1.3 失效传播三机制（新字段必须挂进这里才参与 stale 判定）

1. `strip_media_on_narr_change`（[shots.py:158](../../app/services/anim_pipeline/shots.py#L158)）：文案相似度 <0.55 剥全部媒体回 planned；槽变长 >0.3s 清视频保图；
2. `enhance_keyframes` 重置（[director2.py:3130](../../app/services/anim_pipeline/director2.py#L3130)）：增强改写了提示词的镜若已有媒体 → 回 planned 清媒体（新提示词配旧图=失配）；
3. `gen_narr_sha` 指纹：生成时烙、装配端比对亮灯"文案已变"（[anim_draft.py:1746](../../app/services/anim_draft.py#L1746)）。

### 1.4 本轮架构摸底的两个关键发现（直接影响反哺设计）

**发现① chain_h3 一条龙绕过 K2 人检**：单镜重规划确认后直达视频的链路（0915 用户令），k2 完 → img_done **机器自动过审** → 同 session 续跑 H3（[anim_service.py:501-516](../../app/services/anim_service.py#L501)）。即"K2 图人检"硬闸只在批量流程成立；一条龙链上从确认到进装配**无人看过任何画面**，而 H3 之后零机检——这是全链质量盲区最大的一段，P1-B video_qc 正好补在这里。

**发现② H3 模型是 FL2VA（首尾帧架构）**：当前 workflow 只喂 `first_frame`（[h3.py:133](../../app/services/anim_pipeline/h3.py#L133) 节点 MiniMaxH3ImageToVideo），模型 `minimax_h3_fl2va` 原生支持 last_frame 输入——P3 镜间末态衔接在模型层零改造，只差节点参数+尾帧提取+配对逻辑。

### 1.5 挂点结论（四个自然挂点，全部反哺项复用）

| 挂点 | 位置 | 适用 |
|---|---|---|
| 终串汇聚点 | k2.run_shot 内 `_scene_eff`+`build_prompt` 之后 | 提示词级检查（prompt_gate 已示范） |
| GPU 相位前置闸区 | `_phase_gpu` 开头（[anim_service.py:456-481](../../app/services/anim_service.py#L456)） | 批级硬闸（时间纪律/政治禁区在此） |
| 产物后检查位 | h3.run_shot 成功路径尾（gen_narr_sha 后、transition 前） | 视频产物机检（P1-B） |
| 失效传播 | strip_media / enhance 重置 / 装配审计三件套 | 新字段的 stale 语义 |

## 二、反哺项详细设计

### P1-B · H3 视频产物机检 `video_qc`（首做，无依赖）

**目标**：补全产线最贵环节（~102s+/镜）的零检查盲区，尤其覆盖 chain_h3 一条龙链。

**挂点**：h3.run_shot 成功路径尾——`gen_narr_sha` 写入之后、`transition("anim_done")` 之前（[h3.py:234-242](../../app/services/anim_pipeline/h3.py#L234)）。新模块 `anim_pipeline/video_qc.py`，h3.py 加一段调用。

**接口**：
```
video_qc.check(mp4_path, shot, doc) -> dict | {}
# 抽 3 帧: t=0.2s(避淡入) / 中点 / t=end-0.3s (ffmpeg, 产线已用)
# 每帧过 glm-4v-flash (复用 k2._vlm_dirty 的 _chat 通道), 三类检查:
#   ① 画面崩坏: 黑屏/花屏/严重撕裂/明显肢体畸变
#   ② 文字残留: 画面出现可读文字 (K2 灭字铁律的 H3 层兜底)
#   ③ 首帧漂移: 首抽帧 vs K2 原图 (两图一次调用, 问"是否同一场景的自然延续")
# 命中 → shot["video_suspect"] = {"kinds": [...], "frames": [...]} + log
```

**与既有闸门关系（不降级论证）**：
- **不阻断 anim_done**：视频已花 102s 生成，标记交人，装配照常用真片（人看标记决定重roll）——与 text_suspect 模式同构（产线已验证的"标记交人检"范式，[k2.py:257](../../app/services/anim_pipeline/k2.py#L257)）；
- 不动 beats=槽/软硬超时/gen_narr_sha 任何时序；不改状态机（不加状态，纯字段标记）；
- 人能看到：qc.py 接触表加 video_suspect 徽章 + anim.html 看板卡加徽章（抄 text_suspect 的 board.js 模式）；
- **stale 语义**：video_suspect 属于"产物属性"，随 video_file 生灭——retry_anim/reroll 换 h3_seed 时自然重查覆盖，无需挂进 strip_media（视频被剥时字段跟着没意义，装配层不读它）。

**失败模式**：VLM 超时/异常 → 跳过检查不标记（fail-open）。合理性：观察闸本就不拦截，漏标只损失一个信号，误标反而浪费人眼；升硬闸时再议 fail-closed。

**成本**：3 帧 × 1-2 次 VLM 调用 ≈ +5s/镜（glm-4v-flash），相对 102s 生成可忽略；ffmpeg 抽帧 <1s。

**验证方案**：① 存量回测——12 docs 已生成的 mp4 全量跑 check，统计命中率，命中样本人工眼验定真假阳性率；② 假阳性 >30% 则调 prompt 或降级只查①②类（客观崩坏/文字），③ 首帧漂移单独验证（拿 ep2/ep3 的镜跑，比对 K2 原图）。

**升级判据（硬闸化条件）**：连续 2 个新集观察数据 = 真阳性命中 ≥3 镜且假阳性 <10% → 在 h3.run_batch 出口加"video_suspect 镜默认不 chain 进装配，需人点确认"（软阻断，人可一键放行）；永不自动重掷视频（成本太高，重roll 决定权在人）。

**回滚**：h3.py 调用处一行注释即失效；模块独立无侵入。

### P2-B · TTS 情绪接动画线（第一步零风险，与 P1-B 并行）

**目标**：把 TTS 线已有的 P5 情绪标注（1-7 档，[boost_service/emotions.py:44](../../app/services/boost_service/emotions.py#L44)）接进动画线节奏参数，治"炫度纪律/密度规则只在 DIRECTOR_SYS 散文里"的定性盲区。

**分两步走（v2 新增约束）**：

**第一步（零风险，先做）——离线对照报告，不改任何产线代码**：
写只读脚本：拉 12 docs 的包情绪（audio job manifest）↔ 镜节奏参数（镜长/首拍变化位置/H3 运动幅度描述），输出"情绪强度 vs 节奏参数"相关性表 + 高强度包（≥6）的镜是否真的拿到了更快的首拍变化/更强的运镜。
- **确证标准**：高强度包的镜首拍变化显著早于/强于低强度包 → 情绪信号值得接；无差异或反相关 → 产线已经隐式跟上了，P2-B 取消（省一次改动）。
- 这一步本身就是"每个节点都在提高"的证明过程：没提高的改动不做。

**第二步（确证后才设计）**：最小落点 = h3.build_prompt 按包情绪加一行运动强度锚（≥6 档加 "dynamic motion with strong energy"、≤2 档加 "calm gentle motion"），纯提示词层增量；**scene_len 闸（prompt_gate）守住稀释风险**。规划层不动（密度宪法/槽位 DP 是结构层，情绪是内容层，不混）。

**依赖**：第一步仅读数据；第二步依赖第一步结论 + prompt_gate 运营数据。

### P2-A · 定妆照接线 i2i（需拍板路线，风险最高，放最后）

**目标**：治"跨镜角色一致性=文本 look 串+独立抽卡"的根本缺口（0923 货不对版实锤的深层病根）。

**⚠️ 与既有质量基线的冲突预检（v2 核心）**：K2 主链是 2ST 两段式最爱配方（0911 用户 A/B 定稿，ColorMatchV2 拉回段1 防漂色）。**任何直接改主链 workflow 的方案都可能动坏出图质量基线**——这正是"第 X 步把质量降下去"的头号风险。因此：

**路线 A1（推荐）：旁路 opt-in，不动主链**
- 新增 `build_workflow_i2i`（变体 workflow：+LoadImage 定妆照 → VAEEncode → 按 denoise≈0.65 走 2ST 同款两段式），只在**试镜板/单镜重roll** 可选（opt-in 参数），主链 build_workflow 一字不动；
- 试点流程：选一本书 → 同 20 个角色镜 A/B（主链 vs i2i 旁路）→ 用户眼判定稿 → 确证不降质且一致性提升 → 再议"角色镜默认走旁路"；
- 角色镜判定复用 `_inject_char_looks` 的命中逻辑（[k2.py:182](../../app/services/anim_pipeline/k2.py#L182) 已有角色名×画面句检测）；
- **stale 语义**：定妆照路径记入 shot（如 `ref_sheet`），look 变更时定妆照 md5 自动重渲机制已有（[character_sheets.py:107](../../app/services/anim_pipeline/character_sheets.py#L107)）——i2i 镜在定妆照变更后需回 planned（挂进 strip_media 同位置的一个新分支：ref 变→图失效）。

**路线 A2（不推荐）：ControlNet/IPAdapter 类参考节点**——引入新节点栈=新变量，与"最小改动"原则冲突，仅 A1 失败后再议。

**拍板项**：是否按 A1 走（默认推荐）；试点书选哪本。

### P3 · 镜间末态衔接（FL2VA 尾帧，opt-in，调研已完成）

**目标**：同场相邻镜的运动衔接（治"段落间衔接生硬"类反馈的动画层版本）。

**架构事实（本轮亲证）**：模型 `minimax_h3_fl2va` 原生支持首尾帧；当前节点 133 只喂 first_frame。改造 = 节点加 `last_frame` 输入 + ffmpeg 抽上镜尾帧（t=end-0.05s）存 `img/{sid}_tail.png` + 配对逻辑（同 arc 相邻镜才配，跨场/品牌镜不配）。

**风险与对策**：
- last_frame 锁死整段走向，中间自由度降 → **opt-in 字段**（shot 级 `link_prev: true`，默认关），只给用户点名的"衔接生硬"场启用；
- 尾帧提取的时序依赖（下镜 K2 图完成时上镜视频必须已存在）→ 只在 h3 批内相邻镜顺序生成时配对，redo 单镜不带 link；
- 与 beats=槽拉齐铁律不冲突：尾帧只约束画面走向，不约束时长（时长仍由音频槽说了算）。

**拍板项**：是否立项（默认建议缓——等 P1-B 上线后用 video_qc 的首帧漂移数据先量化"镜间跳切"实际发生率，有数据再决定值不值得做）。

### P0' · prompt_gate 观察模式运营（已落地项的升级判据）

- **运营**：跑满 2 个新集（新生成提示词全部带换词版 PROTECT_TAIL + gate 标记）后拉数据：hard_roots 命中率、来源分布（画面句 vs 拼装层）；
- **升级判据**：画面句来源命中持续 >2% → 在 `_phase_gpu` 闸区加"prompt_gate hard 命中即 auto_fix 同款处理（换词→复扫→修不了 flag 跳卡）"——与政治禁区闸同构，不是新机制；
- **永不升级**：subject_suspect/scene_len 保持观察（启发式信号，升硬闸误伤率高）。

## 三、实施顺序与依赖

```
第一步  P1-B video_qc（无依赖，挂点清晰，补最大盲区）
        └─ 验收: 存量回测命中率报告 + 假阳性眼验 + qc/看板徽章可见
第二步  P2-B 第一步 离线情绪对照报告（零风险并行）
        └─ 验收: 相关性表 + 接/不接的结论
第三步  P0' prompt_gate 运营数据拉取（随新集生成自然积累，无代码）
第四步  [拍板后] P2-A A1 旁路试点（依赖: 用户拍板路线+试点书）
第五步  [视数据] P3 尾帧立项（依赖: P1-B 的首帧漂移/镜间跳切量化数据）
```

每步独立验收、独立回滚，任一步证伪（"没提高"）即停，不带病进下一步。

## 四、全局"只升不降"六条纪律

1. **五个代码硬闸不动**：timeline_violations / 政治禁区 auto_fix / 骨架场 / GPU 锁 / 音频先行——新闸只加不删不改语义；
2. **四个人检硬闸不动**：🎧口播验收 / 🎨风格绑定 / 📜立意人闸 / 🔍K2 过审——新能力只给人**更多**信息（video_suspect 徽章），不替人做决定；chain_h3 自动过审是既有用户令设计，不回头改；
3. **主链 workflow 冻结**：2ST 最爱配方（k2）与 H3 I2V 真相图（102.4s/10s）不动，变体走旁路 opt-in（P2-A A1 / P3 link_prev）；
4. **新观察闸一律 fail-open + 升级判据前置**，数据不到不升硬闸；启发式信号永不升硬闸；
5. **新字段三问**：谁生产？谁消费？stale 怎么传播？——答不上来不入 shots.json（video_suspect=产物属性随 video 生灭，ref_sheet=挂 strip_media）；
6. **每步带存量回测 + 一行回滚**：改动前先证明能抓住已知问题（回测），改动后能证明不误伤（假阳性率），回滚成本低到可以随时停。
